# Roadmap

## Done

- **Plugin manifest SDK** — full PRD: [docs/prds/0010-plugin-manifest-sdk.md](prds/0010-plugin-manifest-sdk.md), scope decision on distribution: [docs/adrs/0007-plugin-manifests-are-declarative-and-unsigned.md](adrs/0007-plugin-manifests-are-declarative-and-unsigned.md), field reference: [docs/manifest.md](manifest.md). The `*.tool.json` format already existed and was already enforced; what it lacked was a spec, a version, and any way to check a file against it. Landed: **`manifest_version`**, where absence means 1 (so all 93 shipped manifests load byte-for-byte unchanged) and a version this build does not know is *refused* rather than read under v1 rules, because registering a tool whose sandbox policy is not the one its author wrote is the failure a version key exists to prevent. **A pure validator** (`src/tools/manifest.zig`, no I/O, 11 unit tests) that reports the file and the offending key and separates errors (the loader refuses it, or accepts it and does something else) from warnings (it loads and does nothing) — the second class is the point, since the loader ignores unknown keys, so `"fs_prefix"` for `"fs_prefixes"`, a `fuel` above the 10B ceiling, or a `tool_allow` with no `tool_call` all load clean and quietly grant nothing. **`clanker plugins list|validate|new`**, fitted onto the noun `/plugins` and `/api/plugins` already use (`list` delegates to the same `cmd_plugins` guest rather than becoming a second listing); `validate` takes a file or a directory and exits non-zero on errors only, so it can guard a script; `new <name>` writes a manifest and a Zig guest that build and validate as they stand. **One packaging affordance**: a `wasm` value with no path separator now resolves beside its own manifest, so `{name.tool.json, name.wasm}` in one directory is a plugin that works wherever it was unpacked — every shipped manifest names a path with a separator, so this is a no-op for all of them. All 93 manifests validate with zero errors *and* zero warnings, pinned by a test. Live-verified end to end: a scaffolded tool was built, found through the lazy catalog (94 tools, the model spent one `load_tools` call on it) and called correctly on a real DeepSeek run. Fixed along the way, all found by writing the reference against the code: `exec_allow` empty was described as "the harness default set (`git`, `rg`, `ast-grep`, `semcode`, `zig`)" in three places when `host.execAllowed` grants *nothing* to a tool that names nothing — three docs crediting every tool with exec authority it has never had; `wasm` was documented as "relative to the tools directory" when it has always been read relative to the process's cwd; and `category`, in 82 of 93 manifests and read by the `cmd_tools`/`cmd_plugins` guests, was undocumented everywhere. **Deliberately out of scope, in writing**: fetching, installing, signing, publisher identity and a registry index — the manifest is already the security boundary and already enforced, so signing answers a question the sandbox does not ask, while an install path without signing would make running someone else's code one command easier without making it any safer (ADR 0007). Also out: `agent.tools_dir` as a list, which is what still stands between the packaging slice and installing a third-party plugin *alongside* the built-in ones rather than instead of them.

- **REPL/TUI migrated to libvaxis** — `clanker repl` is now `src/tui/repl_vaxis.zig`, built on `github.com/rockorager/libvaxis`'s `vxfw` app framework (user's explicit call, after the agave precedent below was raised and weighed — full replacement, not additive). Working end-to-end and live-verified: real `Agent.run` on a background thread (LLM calls block that thread, not the UI), streamed tokens shown live via a 50ms tick that only runs while a turn is in flight (idle, the app is purely event-driven — no busy loop), tool-call/result lines, a status bar with an animated spinner, `Ctrl-C` (idle quits, mid-stream sets the same `stop_flag` `client.chatStream` already checks), `/quit`, `/exit`, `/q`, `exit`, `quit`, and SIGWINCH handled for free by `vxfw.App` (the hand-rolled self-pipe fix in the old `term.zig` has no equivalent here — not needed). Untrusted text (LLM output, tool results) is control-stripped before rendering, mirroring the CWE-150 fix already in the old `transcript.zig`. Known gaps, not oversights: no slash-command palette (only that fixed quit-command set is handled), no inline `ask_user`/approval UI (falls back to the same default a headless run gets), no manual scrollback (transcript always shows its tail), no session persistence/resume, and tool-call rendering is plain dim lines rather than the old left-bar card style. The hand-rolled REPL it replaced (`src/tui/*`, `cmdRepl`, the pty `tui-test` suite, `util/lineedit.zig`) has since been deleted: about 1,100 lines of `cli.zig` and eight files, on the user's call. `tui/transcript.zig`, `theme.zig`, `syntax.zig` and `width.zig` survive because `clanker run` and the vaxis REPL still render through them. The gaps below are now gaps with no fallback, which is the trade that was accepted.
- **Live status UX** — animated spinner + `⚙ tool` / `↳ ms` status lines cover the gap while the LLM or a tool is running, in both `clanker repl` and `clanker run` (`Agent.on_tool_call` / `on_tool_result` hooks); `clanker run` keeps stdout pipe-clean and puts status on stderr.
- **Streaming** — SSE client with tool-call accumulation and `Agent.on_token` hook; the REPL streams tokens live.
- **Web UI plugin** — internal `webui` WASM tool served at `GET /` by `clanker serve`; real multi-turn chat via a `session` id, and a `\x01{"type":...}` event protocol on `/api/run`'s stream for live tool status.
- **Token budget + compaction** — `compact_threshold_bytes` and `max_total_tokens` (plus per-turn/per-session caps) in agent config; conversation compaction runs before and after turns in the REPL, one-shot runs, and the improve engine.
- **Self-improvement gates** — `zig build`, `zig build test`, `zig build tools`, `zig fmt`, and lint run on every staged change before promotion; exposed as `clanker gate` and reused by `improve-self`.
- **Parallel tools / registry** — heterogeneous tool sources (Zig + AssemblyScript) with `clanker tools list`.
- **Multi-instance peers** — peers in config, `clanker serve` (HTTP), `clanker notify <peer> "<msg>"`, `clanker phonebook`, agent cards at `/.well-known/agent.json`, A2A message handler.
- **MCP server** — `clanker mcp`: stdio JSON-RPC server exposing the tool registry.
- **Execution graphs** — every run recorded to `state/runs/`; ASCII timeline via `clanker graph [run-id]` and `/graph`.
- **Plugins & transforms** — every tool is a WASM plugin; descriptors gate `internal`, `enabled`, `llm`, `config`, `transform`; `after`/`before` transform chains rewrite tool I/O; `/plugins` toggles them.
- **`/goal`** — persistent structured goals steering agent runs; `clanker goal`.
- **Autolearn** — usage aggregation from `state/autolearn.jsonl` + `state/runs/`, roadmap upsert via `clanker autolearn`.
- **Subagents** — `subagent` WASM tool: nested agent runs on a dedicated thread with bounded iterations (`ck_subagent` host fn), gated by `modules.subagents`.
- **RLM / reasoning** — `rlm` WASM tool (recursive sub-LM over input chunks, bounded depth) and the `reasoning` tool; traces persisted to `state/reasoning.jsonl`.
- **Self-review tools** — `std_api` (Zig 0.16 std signature lookup via `ck_std_api`), `symbols` (declaration-site extraction), `zig_check` (per-file `ast-check`/`fmt`), `test_file` (`zig test <file>`), `history` (improve-history review), `roadmap` (planned-items reader), `learnings` (read `state/learnings.md`).
- **Docs** — this roadmap, `README.md`, and `docs/README.md` (reference) maintained in-repo.
- **Chatrooms** — clankers subscribe to named rooms and talk to each other: `chat_*` WASM tools, `clanker chat` CLI, `/api/chat/*` HTTP endpoints, subscription overrides, and per-run inbox injection (`modules.chatrooms`).
- **Token usage stats** — every completion recorded to `state/token_stats.jsonl` at the client choke point; `model_stats` WASM tool, `clanker stats` table, and `GET /api/stats` aggregate per provider/model (calls, tokens, cache hit rate, tok/s, cost).
- **Shared todo lists across rooms** — `todo_add` / `todo_claim` / `todo_close` / `todo_list` WASM tools over a per-room list any subscriber can add to, claim, and close. A todo action is just a chat message (`@todo {...}` text in `state/chatrooms.jsonl`) riding the existing append + peer fan-out; state is derived by an order-independent fold (`src/peers/todos.zig`), and two agents claiming at once resolve deterministically — lowest (ts, id) wins on every replica, and `todo_claim` reports the actual winner.
- **LSP integration** — `lsp` WASM tool answering definition/references questions through zls (one stateless zls session per call over stdio JSON-RPC).
- **Configurable RLM recursion depth** — `max_depth` read from the rlm plugin's `config` block (default 3, clamped to a ceiling of 8 so a misconfigured value stays a setting, not a bill).
- **Per-subagent todo lists** — a nested run gets its own private list (`src/agent/private_todos.zig`): the same `todo_add` / `todo_claim` / `todo_close` / `todo_list` tools called without a `room` (ck_chat routes on the missing field), so an agent keeps one vocabulary for both kinds of list. In-memory, single-owner, never fanned out to peers, discarded when the run returns; the final state is appended to the sub-agent's answer, so the parent sees how far a multi-step run got even when it hit the iteration cap.
- **Subagents can ask the parent** — `ask_user {"parent": true}` in a nested run puts the question to the agent that spawned it, as the third target next to the human and `"peer"`. The concurrency decision the plan called for went to the *re-entrant answer path*, not a queue at the parent's next turn boundary: `ck_subagent` joins the nested thread, so the parent never reaches a turn boundary while its sub-agent waits (a queue deadlocks by construction) — and that same join means the parent is parked with no tool of its own in flight (the subagent tool is `llm: true`, hence sequential), so its transcript is a stable snapshot. The answer is one bounded completion on the parent's provider over that snapshot (`answerAsParent` in `src/agent/loop.zig`, wired as `host.ParentAsk` through `Sandbox.own_ask` → `ck_subagent` → the nested run's `parent_ask`).

- **Web UI ask bridge** — `ask_user` works from the browser (webui-plan 1.1): a streaming run writes `\x01{"type":"ask","id":…,"question":…,"options":[…]}` down its own `/api/run` stream and blocks; the page renders the question as option buttons in the turn card and `POST /api/ask` resolves the wait (the answer must be one of the offered options, byte for byte). An unanswered question times out after `agent.ask_timeout_seconds` (default 120) and degrades to the same "nobody attached" answer a headless run gets, so a closed tab never hangs a run.

- **Confirm before write** — Kimi's permission model, riding the ask bridge (webui-plan 1.2): with `agent.confirm_writes` opted in (`browser`, or `always` for the REPL too; default `never`), a call to a write-capable tool — exec or filesystem access in its descriptor, both of which grant writes, or an explicit `"confirm": true` like `subagent`'s, whose nested run is itself ungated — blocks in the dispatch loop until the human allows or denies it. The question travels as a `\x01{"type":"confirm",…}` stream event with a 400-byte argument preview, answered through the same `POST /api/ask` slot machinery with fixed `allow`/`deny` options; read-only tools carry `"confirm": false` so reads keep running free. Anything short of an explicit allow (deny, timeout, closed tab, piped stdin) refuses the call and tells the model the user declined. Headless runs, the improve loop, and nested sub-agents never install a channel, so no config value can gate them on an answer nobody is there to give.

- **Eval definitions under the gate** — `evals/` grew cases for the self-review tools (`std_api`, `zig_check`, `symbols`), each asserting the shape of the answer rather than toolchain- or content-sensitive text. And the definitions themselves are now tested: `Eval.loadAll` skips a file it cannot parse (`catch continue`), so a malformed eval silently stopped being run — `zig build test` now parses every shipped `*.task.json`, rejects a task eval with no prompt or no criteria, and cross-checks each `requires_tool` against the shipped manifests so a tool rename can no longer strand an eval at a permanent score of 0.

- **`recent_commits` tool** — the Autolearn item asking for a dedicated tool for the recurring "summarize the last 3 git commits" task: one read-only call (`git log` with a fixed argv, `{"count": N}` clamped to 1..50) returning one `hash  date  subject  (author)` line per commit, instead of a full agent loop over the general `git` tool.

- **Terminal control stripping** — the agave-inspired sanitization gap closed: a shared strip-pass in `src/tui/transcript.zig` drops C0 controls (except `\n`/`\t`), DEL, and UTF-8-encoded C1 controls at the chokepoints untrusted text enters the renderer — `MdStream.feed` (prose and fenced code alike, including bytes held back across chunk boundaries) and the tool cards' args preview and result body. A stripped ESC leaves the rest of its would-be escape sequence behind as inert printable text, deliberately: the pass stays stateless instead of tracking CSI sequences across stream chunks. Theme-emitted ANSI is written around the sanitized text, never through it.

- **Plan mode** — a run that proposes instead of executing (webui-plan 2.2): `{"plan": true}` on `/api/run` sets `Agent.plan_mode`, which threads a plan-mode block into the system prompt *and* hard-refuses write-capable tool calls in the dispatch loop — the same `needsConfirm` predicate confirm-before-write gates on, so what a viewer would be asked about and what plan mode refuses can never drift. Read-only research runs free; the answer is a numbered plan. The page has a Plan toggle beside Run, badges the proposal turn, and offers "Apply plan", which re-runs in the same session with plan mode off so the plan is in context and writes work again.

- **Subagent runs recorded as their own graphs** — webui-plan 3.1, the prerequisite for the cross-agent view and the pixel floor's helper sprites. A nested run's graph was always recorded but under the same second-resolution `run-<ts>` id as everything else, so a sub-agent spawned in the parent's second silently overwrote a sibling or collided with the parent. Nested runs now get a nanosecond `sub-<ns>` id (`Agent.run_id_override`), and the link runs both ways: the child's graph carries `parent_run_id` (threaded parent → sandbox → `ck_subagent` → `runNested`), and the child's answer carries a trailing `[subagent run: sub-<ns>]` line, which lands in the parent's tool-node output preview — so a viewer can walk from the parent's timeline into the nested one. `cmd_graph` round-trips and lists the new field.

- **Themed output: Catppuccin (4 flavours) + Tokyo Night (3 variants)** — `src/tui/theme.zig`'s `Theme.select` picks a named palette via `CLANKER_THEME` (`mocha`/`catppuccin`, `latte`, `frappe`/`frappé`, `macchiato`, `tokyonight`, `storm`/`tokyonight-storm`, `day`/`tokyonight-day`, plus `mono`/`default`), consumed by both `clanker run`/`clanker repl` (ANSI truecolor escapes) and the vaxis REPL (`src/tui/repl_vaxis.zig`, via `Theme.rgb` for cell colours). Every palette's hex values are pulled from the upstream source rather than a screenshot or prose summary — Catppuccin from `catppuccin/palette`'s `palette.json`, Tokyo Night from `folke/tokyonight.nvim`'s own generated `extras/lua/tokyonight_*.lua` colorschemes — and role assignment (which colour means "keyword", "string", "error", …) follows each project's own style guide/highlight groups rather than an eyeballed analogy to Mocha. The four Catppuccin flavours share one role mapping and the three Tokyo Night variants share another, each built by a small comptime `*Theme(comptime palette: type) Theme` function so the mapping can't drift between flavours by a hand-copied field slipping. One documented quirk: Tokyo Night Storm and Night are byte-identical in this theme (upstream, they differ only in background shade, and `Theme` has no background field — it only colours text). The web UI (`tools/zig/webui/app.css`/`app.js`/`index.html`) got matching `data-theme` blocks and cycle entries so the toggle covers the same set. 14 unit tests in `theme.zig` (up from the original 5 for Mocha's byte-for-byte hex + role checks).

- **Fuzzy provider/model picker, both surfaces** — the composer's `<select>` (webui-plan 2.4) and the vaxis REPL each got a Kimi Code-style picker instead of a plain dropdown/nothing at all: type-to-filter subsequence matching (`fuzzyMatch`, the same forgiving-order algorithm the web UI's command palette and saved-prompt list already used — one notion of "fuzzy" reused rather than a second one invented for the REPL's copy), grouped by provider (config order, so unfiltered already reads that way), context window and $/1M pricing shown inline per entry. `/api/providers` now also emits `cost_per_1m_input`/`cost_per_1m_output` per model (`handleProviders` in `src/cli.zig`) so the web UI has something to show. Web UI: the visible search box (`#model-search`/`#model-list`) is a second view onto the pre-existing hidden `<select>`, which stays the one thing `runOptions()`/localStorage/`renderContextMeter()` read — selecting an entry sets its value and dispatches `change`, so nothing downstream had to change. REPL: `/model` (bare, or `/model <seed query>`) opens a modal box (`Model.picker_open`, `handlePickerKey`) that owns every keystroke until Enter/Escape; selecting an entry copies the chosen provider with `default_model` overridden onto `self.provider` for the *next* turn — `self.messages` is untouched, so the switch lands mid-conversation, not as a new session. Model list is flattened once at REPL startup (`buildModelCandidates`, config doesn't change mid-session) rather than re-walking `cfg.providers` per keystroke.

- **REPL manual scrollback** — PgUp/PgDn page the vaxis REPL transcript by a screenful with one line of overlap; Home jumps to the top, End/Esc return to the tail (at the tail, Home/End keep their TextField cursor meaning). The anchor (`Model.view_end`) is an absolute line index, so a scrolled-up view is frozen — streamed appends can't yank it — and the status bar shows `[scroll -N]` while off the tail; submitting a task snaps back. Per `docs/prds/0005-repl-tui.md`'s widget mapping this is the hand-rolled offset on the existing `tailStart` render path, not `vxfw.ScrollView`; the pure paging/clamping math has its own unit tests. Search deliberately not included — paging only (maci0/clanker#80).

- **REPL slash-command registry** — one static `command_registry` (name, aliases, args, one-line help, action) is the single source of truth: `submit()` dispatches through it (pure `parseCommand` + a `runCommand` switch; `isQuitCommand` and `runSlashCommand` deleted) and `printHelp`'s command section is generated from it, so a command can no longer land undocumented — the property the deleted REPL's `:help` had. Unknown `/command` input prints `[unknown command: … — try /help]` into the transcript instead of going to the LLM; bare text (including bare `exit`/`quit`) behaves as before, and `/model <query>` seeding survives via generic args-after-name parsing. Tests pin the generated-help-mentions-every-spelling property (maci0/clanker#81).

- **REPL inline shell escape (`!cmd`)** — a `!`-prefixed line in the vaxis REPL runs locally and prints its output into the transcript, instead of falling through to the LLM as a task (the Pi-parity gap below). `submit()` intercepts it ahead of `parseCommand`, so the REPL now has three input modes decided in one place: `!` escape, `/` command, agent task — and only the third costs a token. It is deliberately **not** a shell: `splitShellArgs` builds one fixed argv (whitespace-separated, with `'…'`/`"…"` grouping a single argument and no backslash escapes) and hands it to `host.execUnderPolicy`, a new non-WASM entry point onto the same ck_exec gate every tool goes through. The gate itself was factored out rather than copied — `host.execDenial` is now the one place the argv-level decision lives (git's verb allowlist, `exec_pattern_allow` strictness, the deny tokens, shell-operator refusal), called by both `ckExec` and the REPL, so the two cannot drift; the child also gets `execEnvironment`'s filtered environment, so an allowed binary still cannot print this project's API keys. The allowlist is derived, not invented: the union of every registered tool's manifest `exec_allow` (today `ast-grep, gh, git, rg, semcode, uv, zig, zls`), so `!` starts with exactly the exec authority clanker already grants itself and not a byte more; `agent.repl_exec_allow` widens it by one explicit config line without widening any tool. Bare `!` prints usage and that list rather than doing nothing. Output is control-stripped through the same CWE-150 pass as every other untrusted string here, capped at 500 transcript lines on top of ck_exec's byte caps, and a non-zero exit is reported as `[! exit N]` so a silent failure cannot read as success. The escape is echoed and Up-recallable like a task. Deliberate non-goals: no pipes, redirections, globs or `$VAR` expansion (there is no shell to expand them, which is the point), no `cwd` override, no stdin, and no `command_registry` entry — a `CommandSpec` matches a spelling exactly or followed by a space, and `!git status` has neither, so `/help`'s escape section is hand-written beside the key bindings for the same reason those are, and a test pins that no registry entry claims a bang spelling.
- **REPL tool-call cards** — tool calls in the vaxis REPL render as the established left-bar card (`╭─ ⚙ name` / `│ args preview` / `╰─ done in Nms`) instead of plain dim lines. Built as pure, unit-tested line builders in `transcript.zig` (`cardPreview` control-strips per the existing CWE-150 rule, flattens newlines/tabs, caps at 400 bytes on a code-point boundary — matching `loop.zig`'s `argsPreview`); one card per tool batch since the agent reports one timing per batch, with wrapped continuation rows re-opening under `│ `. No card-drawing code survived the old REPL's deletion and vaxis renders cells rather than ANSI, so the card is shared plain-string builders, not a reused writer (maci0/clanker#76).

- **Modular providers (native vtable)** — decision: [docs/adrs/0004-providers-are-a-native-vtable-not-wasm.md](adrs/0004-providers-are-a-native-vtable-not-wasm.md). Today a `ProviderKind` is switched on in ~7 places across `src/llm/{client,providers}.zig`, interleaving wire codec, auth strategy, and transport quirks. Target: one native file per provider behind a `Provider` vtable (`buildRequest`/`parseResponse`/`parseStreamEvent`/`authHeaders`/`endpointUrl`) registered in one table, with the shared HTTP/SSE/retry/token-counting core staying one module, so adding a provider is one file not seven edits. WASM-per-provider was weighed and rejected: keys can't enter the sandbox without inverting `env_allow`, and transport is on the per-token hot path. The pure codec is the only WASM-eligible slice and is deferred until an untrusted-plugin-provider need appears. Auth is a separate strategy axis from the wire kind (`api_key` / `oauth_static` / `oauth_refresh`), so a provider like xAI that offers both API-key and OAuth carries the second as a credential-acquisition strategy, not a new wire kind: [docs/adrs/0005-auth-is-a-strategy-axis-separate-from-wire-kind.md](adrs/0005-auth-is-a-strategy-axis-separate-from-wire-kind.md). The upper bound on how far the vtable stretches is Cursor (protobuf over gRPC Connect/HTTP2, PKCE OAuth with JWT refresh, MCP tools, a heartbeat bridge): the codec and auth axes absorb its wire and credential divergence, but its persistent HTTP/2 session needs the transport core extended, a bigger change than a provider file: [docs/cursor-api-notes.md](cursor-api-notes.md). Not started; the ADRs record the target shape.

- **Blind side-by-side model comparison (`clanker compare`)** — the Odysseus gap below, closed. Decision on where the concurrency lives: [docs/adrs/0006-fan-out-concurrency-belongs-to-the-host.md](adrs/0006-fan-out-concurrency-belongs-to-the-host.md). One prompt goes to 2-8 configured provider/model targets at once and the answers come back as `A`, `B`, `C` with nothing saying which model wrote which; a judge model picks a winner, or `--judge none` leaves the pick to the human and `compare --show <id> --pick <letter>` records it. `--synthesize` merges the answers into one as an extra call. Comparisons land in `state/compare/<id>.json` with a `log.jsonl` ledger, exactly as `arena` persists a match. The split mirrors arena's: `tools/zig/compare_blind.zig` imports nothing from the guest ABI and is unit-tested on the host (12 cases), `tools/zig/compare.zig` is the shell that resolves targets, makes the calls, persists and renders, and `cmdCompare` in `src/cli.zig` only builds the tool's input, so an agent calling the tool and a person typing the subcommand get one implementation rather than two. **The concurrency is a new host function, `ck_llm_many`**, not a loop in the guest: a wasm guest is single-threaded, so N models asked one at a time cost the sum of their latencies. The host fans the targets out one thread each and joins them all before returning, the same shape `ck_swarm` already uses for nested agents, so the batch costs the slowest model and the caller never sees a half-finished one. It carries the same `"llm": true` descriptor grant and charges the same session token budget a loop of `ck_llm` would have; one failing target is a failing element (with the provider's own error text attached), never a failing call, so a comparison of five models where one is out of credit is still a comparison of four. **Blindness is three separate mechanisms**, because any one of them alone leaks: the display order is a permutation seeded from the comparison id rather than the order the targets were configured in (stable enough to re-render a stored comparison, not the order a reader would otherwise correctly guess), the labels are positional and never derived from the provider, and each entrant's own provider/model names are struck out of its own answer before anyone reads it, since a model that opens "As DeepSeek, I would..." has un-blinded itself. The stored document is written in blind order too, so the file does not leak what the render withholds. **Deliberate non-goals**: this is not `providers check`, which pings for connectivity and latency and says nothing about answer quality, and it is not `arena`, where the models argue against each other over rounds and see each other's moves; here they answer once and never see each other. `judge = "auto"` resolves to `default_provider` rather than hunting for a provider that is not an entrant, because the guest cannot tell a configured provider from a reachable one and `config.toml` ships half a dozen stanzas most machines have no key for; when the judge is itself an entrant the verdict carries a caveat saying so, rather than the tool silently returning no verdict at all. **Still open**: no REPL or web UI view (a `/compare` slash command and a browser side-by-side with a pick button are the obvious next slice, and the tool already answers structured `answers`/`verdict` arrays for one to render); no per-entrant temperature or system-prompt variation, so this compares models and not prompts; and nothing feeds a comparison's outcome back into routing, which stays a manual `--provider` decision. Fixed along the way: `src/tools/registry.zig`'s "a tool that calls the model says so in its descriptor" gate scanned for `lib.llm(`/`lib.llmWith(`/`lib.subagent(` only, so `arena` (which only ever calls `lib.llmSystem`) was already invisible to it and `compare` would have been too; both helpers are now on the list.

- **Feature audit vs. Pi and Odysseus (2026-08-12)** — compared clanker against two current open-source agent projects at the user's request: **[Pi](https://github.com/earendil-works/pi)** (mariozechner's TypeScript coding-agent toolkit — `pi-ai` unified multi-provider LLM API, `pi-agent-core` tool-calling runtime, `pi-coding-agent` CLI, `pi-tui` a differential-rendering terminal UI library, `pi-mom` a Slack bot front-end, `pi-pods` for vLLM GPU-pod management) and **[Odysseus](https://github.com/odysseus-dev/odysseus)** (PewDiePie's self-hosted "AI workspace" — chat/agents/deep-research/documents/email/notes+calendar/gallery, Docker Compose deployment, 22k+ stars). Four gaps were real and worth planning for; the first has since shipped, three are open:
  - **No inline shell escape in the REPL.** (2026-08-13: done, see **REPL inline shell escape (`!cmd`)** under Done.) Pi's CLI runs a shell command directly via a `!` prefix inside the interactive session, without leaving the agent loop or spending a tool call. Clanker's REPL had only two input modes — a `/`-prefixed command or an agent task (`parseCommand`/`looksLikeSlashCommand`, `src/tui/repl_vaxis.zig`) — so a bare `!cmd` line fell through to the LLM as a task instead of running locally. One correction to this item as written: there is no `exec` tool to borrow a path from. `ck_exec` is a host import that WASM guests call, gated per tool by its manifest's `exec_allow`, so "the same gate" meant factoring the argv-level decision out of `ckExec` into `host.execDenial` and adding `host.execUnderPolicy` for callers that are not guests — not a raw shell, and not a second copy of the policy either.
  - **No shareable session link.** Pi has `badlogic/pi-share-hf`, a public link for a single session. Clanker already has the pieces this would ride on (`session.branchSession`, session archive/import, `state/sessions/`) but no export-to-a-URL path — would need either a paste-service-style upload or, more in keeping with clanker's local-first design, a `clanker session export <id>` that writes a self-contained HTML transcript (à la the webui's existing raw-string HTML export, which has its own unescaped-interpolation bug flagged in `docs/WEBUI_REVIEW.md`'s history — fix that path before building a second exporter on top of it).
  - **No blind side-by-side model comparison.** Odysseus's "blind side-by-side model testing and synthesis" is a different feature than what clanker already has: `clanker providers check` (`src/cli.zig`'s sweep, `pingWithTimeout`) verifies connectivity/latency, not response quality. A genuine gap would be: send one prompt to N configured models concurrently, show the answers unlabeled, let the user (or a judge model) pick, optionally synthesize a merged answer. Natural fit as a new WASM tool plus a REPL/webui view, reusing the existing multi-provider `client.zig` plumbing. (2026-08-13: done as `clanker compare` plus the `compare` tool and the `ck_llm_many` host function, synthesis included — see **Blind side-by-side model comparison** under Done. The REPL/webui view is the one piece not built; it is listed as still open there.)
  - **No native recurring/scheduled agent runs.** Odysseus ships scheduled agent tasks and CalDAV-synced reminders as first-class workspace features. Clanker has no analogous built-in — recurring runs today depend entirely on an external cron calling `clanker run`/`clanker-improve.sh`/`clanker-review.sh` from outside the binary (see those shell scripts). A `clanker schedule` subcommand (a `state/schedule.json` list of cron-like entries, checked by a lightweight always-on `serve` loop or a `clanker schedule run-due` invoked by the system's own cron) would remove that outside dependency, but is a genuinely new subsystem, not a small addition — worth a PRD before starting, not a same-session build.
  - **Not adopting, and why:** Odysseus's 2FA/multi-user auth doesn't apply to `clanker serve`'s current trust model — it binds to `127.0.0.1` only and refuses any other `Host`/`:authority` (`unexpectedHost` in `src/cli.zig`), so there is no network-facing surface to authenticate against unless remote or multi-tenant exposure becomes an explicit goal. Pi's own docs note it has *no* built-in permission system and runs with the user's full process permissions — the opposite direction from clanker's `ck_*`/descriptor sandbox, so this is a validation of the existing design, not a gap to close.
