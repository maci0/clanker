# Roadmap

## Done

- **Plugin manifest SDK** — full PRD: [docs/prds/0010-plugin-manifest-sdk.md](prds/0010-plugin-manifest-sdk.md), scope decision on distribution: [docs/adrs/0007-plugin-manifests-are-declarative-and-unsigned.md](adrs/0007-plugin-manifests-are-declarative-and-unsigned.md), field reference: [docs/manifest.md](manifest.md). The `*.tool.json` format already existed and was already enforced; what it lacked was a spec, a version, and any way to check a file against it. Landed: **`manifest_version`**, where absence means 1 (so every shipped manifest loads byte-for-byte unchanged) and a version this build does not know is *refused* rather than read under v1 rules, because registering a tool whose sandbox policy is not the one its author wrote is the failure a version key exists to prevent. **A pure validator** (`src/toolhost/manifest.zig`, no I/O, 11 unit tests) that reports the file and the offending key and separates errors (the loader refuses it, or accepts it and does something else) from warnings (it loads and does nothing) — the second class is the point, since the loader ignores unknown keys, so `"fs_prefix"` for `"fs_prefixes"`, a `fuel` above the 10B ceiling, or a `tool_allow` with no `tool_call` all load clean and quietly grant nothing. **`clanker plugins list|validate|new`**, fitted onto the noun `/plugins` and `/api/plugins` already use (`list` delegates to the same `plugins` guest rather than becoming a second listing); `validate` takes a file or a directory and exits non-zero on errors only, so it can guard a script; `new <name>` writes a manifest and a Zig guest that build and validate as they stand. **One packaging affordance**: a `wasm` value with no path separator now resolves beside its own manifest, so `{name.tool.json, name.wasm}` in one directory is a plugin that works wherever it was unpacked — every shipped manifest names a path with a separator, so this is a no-op for all of them. Every manifest in `tools/manifests` validates with zero errors *and* zero warnings, pinned by a test that walks the directory. Live-verified end to end: a scaffolded tool was built, found through the lazy catalog (94 tools, the model spent one `load_tools` call on it) and called correctly on a real DeepSeek run. Fixed along the way, all found by writing the reference against the code: `exec_allow` empty was described as "the harness default set (`git`, `rg`, `ast-grep`, `semcode`, `zig`)" in three places when `host.execAllowed` grants *nothing* to a tool that names nothing — three docs crediting every tool with exec authority it has never had; `wasm` was documented as "relative to the tools directory" when it has always been read relative to the process's cwd; and `category`, in most manifests and read by the `tools`/`plugins` guests, was undocumented everywhere. **`agent.tools_dir` is now a list** ([PRD 0022](prds/0022-out-of-tree-tools.md)): a string still parses as one entry, an array loads every directory, later-listed wins on a name collision. **Deliberately out of scope, in writing**: fetching, installing, signing, publisher identity and a registry index — the manifest is already the security boundary and already enforced, so signing answers a question the sandbox does not ask, while an install path without signing would make running someone else's code one command easier without making it any safer (ADR 0007).

- **Scheduled runs (`clanker schedule`)** — `clanker schedule add|list|remove|enable|disable|run|run-due|log` over `state/schedule.json`, with every fire recorded in `state/schedule/log.jsonl`. Five-field cron subset (`*`, numbers, lists, `a-b`, `*/n`, `a-b/n`; Sunday is 0 or 7; Vixie's dom-or-dow rule), parsed and evaluated by pure, I/O-free code in `src/schedule/cron.zig` and checked against a brute-force minute scan. Fields are read at a fixed per-entry UTC offset (`--tz-offset`), never a DST-aware zone. A missed window fires **once** and is not backfilled: a machine that slept through a day of a `*/5` entry runs it once on wake, counts the rest into the ledger's `skipped`, and resumes on the normal grid. `run-due` claims a window before it calls the model (so a killed run is at-most-once, not a crash loop) and holds a non-blocking flock for its whole sweep, so a per-minute cron cannot stack sweeps. Nothing fires on its own — the system's own cron calls `run-due`; there is no `serve` loop. See [PRD 0009](prds/0009-schedule.md), [ADR 0009](adrs/0009-schedule-fires-on-fixed-utc-offsets.md) and [ADR 0008](adrs/0008-the-scheduler-is-cron-driven-not-a-daemon.md). **The web UI view shipped** (2026-08-13): a Schedule tab over `GET /api/schedule` (every entry with its next fire time, plus the last 20 ledger records) and `POST /api/schedule/<id>` `{"enabled":bool}`. Read-and-toggle on purpose, the same line the Arena and Compare views draw: firing an entry is an agent run and `serve` answers one request per connection, so `run` and `run-due` stay with cron and the terminal. Adding stays there too, because `add` has to refuse a spec that never fires and say which of the spec and the task was wrong, and a browser form that quietly accepted one would be worse than no form. Two details the view had to get right rather than inherit: times render at each entry's own fixed UTC offset (rendering them in the browser's locale would make a row that says 09:00 mean something other than the 09:00 the cron field names), and `next_run` is *absent* rather than zero when an entry can never fire, so the page can separate "paused", which someone chose, from a spec that parses to nothing, which nobody did. The empty ledger names the reason it is nearly always empty: nothing is calling `run-due`. Still not built: a WASM tool over the schedule, so an agent still cannot read or change its own timetable.
- **REPL/TUI migrated to libvaxis** — `clanker repl` is now `src/tui/repl.zig`, built on `github.com/rockorager/libvaxis`'s `vxfw` app framework (user's explicit call, after the agave precedent below was raised and weighed — full replacement, not additive). Working end-to-end and live-verified: real `Agent.run` on a background thread (LLM calls block that thread, not the UI), streamed tokens shown live via a 33ms tick that only runs while a turn is in flight (idle, the app is purely event-driven — no busy loop), tool-call/result lines, a status bar with an animated spinner, `Ctrl-C` (idle quits, mid-stream sets the same `stop_flag` `client.chatStream` already checks), `/quit`, `/exit`, `/q`, `exit`, `quit`, and SIGWINCH handled for free by `vxfw.App` (the hand-rolled self-pipe fix in the old `term.zig` has no equivalent here — not needed). Untrusted text (LLM output, tool results) is control-stripped before rendering, mirroring the CWE-150 fix already in the old `transcript.zig`. Known gaps at the time have mostly closed since: the slash-command registry, manual scrollback, session persistence/resume, left-bar tool-call cards, and (2026-08-13) the inline `ask_user`/confirm-before-write bridge have all shipped (see the entries below and Planned for what remains). The hand-rolled REPL it replaced (`src/tui/*`, `cmdRepl`, the pty `tui-test` suite, `util/lineedit.zig`) has since been deleted: about 1,100 lines of `cli.zig` and eight files, on the user's call. `tui/transcript.zig`, `theme.zig`, `syntax.zig` and `width.zig` survive (joined since by `sanitize.zig` and `stats.zig`) because `clanker run` and the vaxis REPL still render through them. The gaps below are now gaps with no fallback, which is the trade that was accepted.

PRD: [docs/prds/0004-autoresearch.md](prds/0004-autoresearch.md), ADR: [docs/adrs/0003-autoresearch-is-a-generic-harness-loop.md](adrs/0003-autoresearch-is-a-generic-harness-loop.md).

- **Shared todo lists across rooms** — *superseded and removed.* Built as `todo_*` WASM tools over a per-room list derived by an order-independent fold, then retired once the Kanban board covered the same need (ADR 0002). `src/peers/todos.zig` is gone, and a `todo_*` op that names a `room` now fails with a pointer to `kanban_add`/`kanban_move`/`kanban_claim`/`kanban_list` (`src/sandbox/host.zig`). The surviving `todo_*` path is a run's own private checklist, which is a different feature (see below).
- **LSP integration** — `lsp` WASM tool answering definition/references questions through zls (one stateless zls session per call over stdio JSON-RPC).
- **Configurable RLM recursion depth** — `max_depth` read from the rlm plugin's `config` block (default 3, clamped to a ceiling of 8 so a misconfigured value stays a setting, not a bill).
- **Per-subagent todo lists** — a nested run gets its own private list (`src/agent/private_todos.zig`): the same `todo_add` / `todo_claim` / `todo_close` / `todo_list` tools called without a `room` (ck_chat routes on the missing field), so an agent keeps one vocabulary for both kinds of list. In-memory, single-owner, never fanned out to peers, discarded when the run returns; the final state is appended to the sub-agent's answer, so the parent sees how far a multi-step run got even when it hit the iteration cap.
- **Subagents can ask the parent** — `ask_user {"parent": true}` in a nested run puts the question to the agent that spawned it, as the third target next to the human and `"peer"`. The concurrency decision the plan called for went to the *re-entrant answer path*, not a queue at the parent's next turn boundary: `ck_subagent` joins the nested thread, so the parent never reaches a turn boundary while its sub-agent waits (a queue deadlocks by construction) — and that same join means the parent is parked with no tool of its own in flight (the subagent tool is `llm: true`, hence sequential), so its transcript is a stable snapshot. The answer is one bounded completion on the parent's provider over that snapshot (`answerAsParent` in `src/agent/loop.zig`, wired as `host.ParentAsk` through `Sandbox.own_ask` → `ck_subagent` → the nested run's `parent_ask`).

- **Web UI ask bridge** — `ask_user` works from the browser (webui-plan 1.1): a streaming run writes `\x01{"type":"ask","id":…,"question":…,"options":[…]}` down its own `/api/run` stream and blocks; the page renders the question as option buttons in the turn card and `POST /api/ask` resolves the wait (the answer must be one of the offered options, byte for byte). An unanswered question times out after `agent.ask_timeout_seconds` (default 120) and degrades to the same "nobody attached" answer a headless run gets, so a closed tab never hangs a run.

- **Confirm before write** — Kimi's permission model, riding the ask bridge (webui-plan 1.2): with `agent.confirm_writes` opted in (`browser` for the web UI; `always` also gates the REPL via its modal bridge; default `never`), a call to a write-capable tool — exec or filesystem access in its descriptor, both of which grant writes, or an explicit `"confirm": true` like `subagent`'s, whose nested run is itself ungated — blocks in the dispatch loop until the human allows or denies it. The question travels as a `\x01{"type":"confirm",…}` stream event with a 400-byte argument preview, answered through the same `POST /api/ask` slot machinery with fixed `allow`/`deny` options; read-only tools carry `"confirm": false` so reads keep running free. Anything short of an explicit allow (deny, timeout, closed tab, piped stdin) refuses the call and tells the model the user declined. Headless runs, the improve loop, and nested sub-agents never install a channel, so no config value can gate them on an answer nobody is there to give.

- **REPL ask/confirm bridge** — the vaxis REPL wires `Agent.ask_fn` / `confirm_fn` to a modal on the render thread (`askOnRunThread` / `handleAskKey` / `drawAskModal` in `src/tui/repl.zig`). `ask_user` reaches a human; with `agent.confirm_writes = "always"`, write-capable tools gate on allow/deny. Escape, timeout (`agent.ask_timeout_seconds`), and turn abandon decline. One question at a time. See [PRD 0005](prds/0005-repl-tui.md).

- **Eval definitions under the gate** — `evals/` grew cases for the self-review tools (`std_api`, `zig_check`, `symbols`), each asserting the shape of the answer rather than toolchain- or content-sensitive text. And the definitions themselves are now tested: `Eval.loadAll` skips a file it cannot parse (`catch continue`), so a malformed eval silently stopped being run — `zig build test` now parses every shipped `*.task.json`, rejects a task eval with no prompt or no criteria, and cross-checks each `requires_tool` against the shipped manifests so a tool rename can no longer strand an eval at a permanent score of 0.

- **`recent_commits` tool** — the Autolearn item asking for a dedicated tool for the recurring "summarize the last 3 git commits" task: one read-only call (`git log` with a fixed argv, `{"count": N}` clamped to 1..50) returning one `hash  date  subject  (author)` line per commit, instead of a full agent loop over the general `git` tool.

- **Terminal control stripping** — the agave-inspired sanitization gap closed: a shared strip-pass in `src/tui/sanitize.zig`, used from `transcript.zig`, drops C0 controls (except `\n`/`\t`), DEL, and UTF-8-encoded C1 controls at the chokepoints untrusted text enters the renderer — `MdStream.feed` (prose and fenced code alike, including bytes held back across chunk boundaries) and the tool cards' args preview and result body. A stripped ESC leaves the rest of its would-be escape sequence behind as inert printable text, deliberately: the pass stays stateless instead of tracking CSI sequences across stream chunks. Theme-emitted ANSI is written around the sanitized text, never through it.

- **Plan mode** — a run that proposes instead of executing (webui-plan 2.2): `{"plan": true}` on `/api/run` sets `Agent.plan_mode`, which threads a plan-mode block into the system prompt *and* hard-refuses write-capable tool calls in the dispatch loop — the same `needsConfirm` predicate confirm-before-write gates on, so what a viewer would be asked about and what plan mode refuses can never drift. Read-only research runs free; the answer is a numbered plan. The page has a Plan toggle beside Run, badges the proposal turn, and offers "Apply plan", which re-runs in the same session with plan mode off so the plan is in context and writes work again.

- **Subagent runs recorded as their own graphs** — webui-plan 3.1, the prerequisite for the cross-agent view and the pixel floor's helper sprites. A nested run's graph was always recorded but under the same second-resolution `run-<ts>` id as everything else, so a sub-agent spawned in the parent's second silently overwrote a sibling or collided with the parent. Nested runs now get a nanosecond `sub-<ns>` id (`Agent.run_id_override`), and the link runs both ways: the child's graph carries `parent_run_id` (threaded parent → sandbox → `ck_subagent` → `runNested`), and the child's answer carries a trailing `[subagent run: sub-<ns>]` line, which lands in the parent's tool-node output preview — so a viewer can walk from the parent's timeline into the nested one. `graph` round-trips and lists the new field.

- **Themed output: Catppuccin (4 flavours) + Tokyo Night (3 variants)** — `src/tui/theme.zig`'s `Theme.select` picks a named palette via `CLANKER_THEME` (`mocha`/`catppuccin`, `latte`, `frappe`/`frappé`, `macchiato`, `tokyonight`, `storm`/`tokyonight-storm`, `day`/`tokyonight-day`, plus `mono`/`default`), consumed by both `clanker run`/`clanker repl` (ANSI truecolor escapes) and the vaxis REPL (`src/tui/repl.zig`, via `Theme.rgb` for cell colours). Every palette's hex values are pulled from the upstream source rather than a screenshot or prose summary — Catppuccin from `catppuccin/palette`'s `palette.json`, Tokyo Night from `folke/tokyonight.nvim`'s own generated `extras/lua/tokyonight_*.lua` colorschemes — and role assignment (which colour means "keyword", "string", "error", …) follows each project's own style guide/highlight groups rather than an eyeballed analogy to Mocha. The four Catppuccin flavours share one role mapping and the three Tokyo Night variants share another, each built by a small comptime `*Theme(comptime palette: type) Theme` function so the mapping can't drift between flavours by a hand-copied field slipping. One documented quirk: Tokyo Night Storm and Night are byte-identical in this theme (upstream, they differ only in background shade, and `Theme` has no background field — it only colours text). The web UI (`ui/app/app.css`/`app.js`/`index.html`) got matching `data-theme` blocks and cycle entries so the toggle covers the same set. Unit tests in `theme.zig` cover every palette's byte-for-byte hex and role assignments.

- **Fuzzy provider/model picker, both surfaces** — the composer's `<select>` (webui-plan 2.4) and the vaxis REPL each got a Kimi Code-style picker instead of a plain dropdown/nothing at all: type-to-filter subsequence matching (`fuzzyMatch`, the same forgiving-order algorithm the web UI's command palette and saved-prompt list already used — one notion of "fuzzy" reused rather than a second one invented for the REPL's copy), grouped by provider (config order, so unfiltered already reads that way), context window and $/1M pricing shown inline per entry. `/api/providers` now also emits `cost_per_1m_input`/`cost_per_1m_output` per model (`handleProviders` in `src/cli.zig`) so the web UI has something to show. Web UI: the visible search box (`#model-search`/`#model-list`) is a second view onto the pre-existing hidden `<select>`, which stays the one thing `runOptions()`/localStorage/`renderContextMeter()` read — selecting an entry sets its value and dispatches `change`, so nothing downstream had to change. REPL: `/model` (bare, or `/model <seed query>`) opens a modal box (`Model.picker_open`, `handlePickerKey`) that owns every keystroke until Enter/Escape; selecting an entry copies the chosen provider with `default_model` overridden onto `self.provider` for the *next* turn — `self.messages` is untouched, so the switch lands mid-conversation, not as a new session. Model list is flattened once at REPL startup (`buildModelCandidates`, config doesn't change mid-session) rather than re-walking `cfg.providers` per keystroke.

- **REPL manual scrollback** — PgUp/PgDn page the vaxis REPL transcript by a screenful with one line of overlap; Home jumps to the top, End/Esc return to the tail (at the tail, Home/End keep their TextField cursor meaning). The anchor (`Model.view_end`) is an absolute line index, so a scrolled-up view is frozen — streamed appends can't yank it — and the status bar shows `[scroll -N]` while off the tail; submitting a task snaps back. Per `docs/prds/0005-repl-tui.md`'s widget mapping this is the hand-rolled offset on the existing `tailStart` render path, not `vxfw.ScrollView`; the pure paging/clamping math has its own unit tests. Search deliberately not included — paging only (maci0/clanker#80).

- **REPL slash-command registry** — one static `command_registry` (name, aliases, args, one-line help, action) is the single source of truth: `submit()` dispatches through it (pure `parseCommand` + a `runCommand` switch; `isQuitCommand` and `runSlashCommand` deleted) and `printHelp`'s command section is generated from it, so a command can no longer land undocumented — the property the deleted REPL's `:help` had. Unknown `/command` input prints `[unknown command: … — try /help]` into the transcript instead of going to the LLM; bare text (including bare `exit`/`quit`) behaves as before, and `/model <query>` seeding survives via generic args-after-name parsing. Tests pin the generated-help-mentions-every-spelling property (maci0/clanker#81).

- **REPL inline shell escape (`!cmd`)** — a `!`-prefixed line in the vaxis REPL runs locally and prints its output into the transcript, instead of falling through to the LLM as a task (the Pi-parity gap below). `submit()` intercepts it ahead of `parseCommand`, so the REPL now has three input modes decided in one place: `!` escape, `/` command, agent task — and only the third costs a token. It is deliberately **not** a shell: `splitShellArgs` builds one fixed argv (whitespace-separated, with `'…'`/`"…"` grouping a single argument and no backslash escapes) and hands it to `host.execUnderPolicy`, a new non-WASM entry point onto the same ck_exec gate every tool goes through. The gate itself was factored out rather than copied — `host.execDenial` is now the one place the argv-level decision lives (git's verb allowlist, `exec_pattern_allow` strictness, the deny tokens, shell-operator refusal), called by both `ckExec` and the REPL, so the two cannot drift; the child also gets `execEnvironment`'s filtered environment, so an allowed binary still cannot print this project's API keys. The allowlist is derived, not invented: the union of every registered tool's manifest `exec_allow` (today `ast-grep, gh, git, rg, semcode, uv, zig, zls`), so `!` starts with exactly the exec authority clanker already grants itself and not a byte more; `agent.repl_exec_allow` widens it by one explicit config line without widening any tool. Bare `!` prints usage and that list rather than doing nothing. Output is control-stripped through the same CWE-150 pass as every other untrusted string here, capped at 200 transcript lines on top of ck_exec's byte caps, and a non-zero exit is reported as `[! exit N]` so a silent failure cannot read as success. The escape is echoed and Up-recallable like a task. Deliberate non-goals: no pipes, redirections, globs or `$VAR` expansion (there is no shell to expand them, which is the point), no `cwd` override, no stdin, and no `command_registry` entry — a `CommandSpec` matches a spelling exactly or followed by a space, and `!git status` has neither, so `/help`'s escape section is hand-written beside the key bindings for the same reason those are, and a test pins that no registry entry claims a bang spelling.
- **REPL per-turn stats and visible compaction** — the vaxis REPL now says what a turn cost and admits when it threw history away. Every completed turn closes with one dim line (`[turn: 1234 in / 567 out · 4.2s · 135.1 tok/s · cache 82% · $0.0031 · ctx 12.3k/128k (10%)]`), and the status bar carries a running context meter and the session's cost so far beside the provider/model. The formatter is a new `src/tui/turn_stats.zig` with *two* callers, not one: `clanker run` prints the identical string on stderr under the same TTY gate its spinner already uses, so the footer `docs/README.md` had been claiming for both surfaces since the old REPL was deleted is true again rather than quietly false — the numbers existed all along, but only as a `log.debug` line in `agent/loop.zig` that nothing at the default level ever showed. Deliberate omissions over confident zeroes: a model with no `cost_per_1m_input`/`cost_per_1m_output` drops the `$` segment entirely, because `$0.0000` reads as "free" when the truth is "unpriced", and a provider that reported no cache accounting drops `cache` rather than showing 0%. Compaction is two different events and both were invisible: `session.compactMessages` trims the oldest messages before every save and is now weighed either side of the call (`[history compacted: dropped 12 messages, freed 48 KB]`, in the same byte units the browser shows for the same conversation), while `Agent.maybeCompactMessages` replaces the middle of the conversation with an LLM summary mid-turn once `agent.compact_threshold_bytes` is passed. The second one is *detected*, not reported: it happens inside `Agent.run`, which only logs it, so `stats.summaryState` recognises the summary message it leaves behind and diffs that against a baseline taken at submit. That is a deliberate shortcut with a named cost — it couples the REPL to loop.zig's placeholder wording — and the proper fix (an `Agent.on_compact` hook beside the existing `on_tool_call`/`on_todos` ones, which the web UI could ride too) is written down in `docs/prds/0005-repl-tui.md` rather than left implied. The context estimate is bytes/4, the same chars-per-token heuristic `session.compactMessages` budgets against and the web UI's own meter divides by, so the terminal's percentage and the browser's agree instead of being two guesses; `cli.zig`'s `transcriptBytes` is now that shared function rather than a second copy of it. All the arithmetic and every string live in the pure module and are unit-tested there (14 cases), since the vaxis event loop is not testable here.
- **REPL tool-call cards** — tool calls in the vaxis REPL render as the established left-bar card (`╭─ ⚙ name` / `│ args preview` / `╰─ done in Nms`) instead of plain dim lines. Built as pure, unit-tested line builders in `transcript.zig` (`cardPreview` control-strips per the existing CWE-150 rule, flattens newlines/tabs, caps at 400 bytes on a code-point boundary — matching `loop.zig`'s `argsPreview`); one card per tool batch since the agent reports one timing per batch, with wrapped continuation rows re-opening under `│ `. No card-drawing code survived the old REPL's deletion and vaxis renders cells rather than ANSI, so the card is shared plain-string builders, not a reused writer (maci0/clanker#76).
- **Session HTML export (`clanker session export <id>`)** — one saved conversation written out as a single self-contained HTML file, default `state/exports/<id>.html` or a path given as a second positional. The Pi-parity gap below, closed on the local-first half only, and the choice is the point: Pi's `pi-share-hf` answers "share a session" with an upload that returns a public URL, which means a service that has to keep running for the link to keep resolving and a transcript (tool output, file paths, whatever the model read) leaving the machine to get there. A file answers the same question with no server, no account and no egress — it opens from `file://`, attaches to a mail or a ticket, and survives clanker being uninstalled. **The upload/URL half is deliberately not built and is a non-goal**, not a deferred phase: nothing in the tree posts a session anywhere, and adding that would be a decision about egress, not a feature increment. **Self-contained is literal**: no script, no stylesheet, no font, no image, no analytics — one `<style>` block, system font stacks, and a test that fails the build if the rendered document ever grows a `<link`, a `src=`, an `@import` or an absolute URL. **Escaping is the correctness core, not a detail.** A session is untrusted text end to end (model output, tool output, an operator-typed title), so every interpolation goes through one escaper covering `& < > " '` in a single pass, and the transcript is rendered as preformatted text rather than re-rendered markdown — emitting markup derived from model output is exactly what an export of untrusted text must not do, and a code fence would have to be un-rendered again anyway. Ordered as the roadmap item demanded: the webui's own raw-string export was fixed first (see below), because building a second exporter on top of a leaky one duplicates the leak. Rendering lives in the `session_export` WASM tool (`tools/zig/session_export.zig`, with `tools/manifests/session_export.tool.json`), unit-tested against a hostile transcript (`<script>`, quotes, `&`, a raw `<` inside a code fence, a `</pre>` breakout in a tool result); `cmdSessionExport` only resolves the id and the destination and then calls the tool.
- **Webui `Export .html` escaping, finished** — the run export in `drawRun` (`ui/app/app.js`) built its page by string concatenation and carried a second, partial escaper beside `core/utils.js`'s `escapeHtml`: a lone `.replace` of `<`, covering one of the five characters that matter. An earlier slice fixed the header fields it had missed (`docs/reviews/webui.md`, "Two bugs found on the way") but left that hand-rolled call in place on the JSON dump, and `<` alone does keep markup out of a `<pre>` — which is precisely why it stayed unexamined. What it did not do is leave the text intact: with `&` unescaped, a run whose text contained the literal characters `&lt;script&gt;` was shown as `<script>`, so the export silently disagreed with the run it claimed to be a copy of. Every interpolation site in that path now goes through the one escaper, and a source-tree test in `src/cli.zig` walks `ui/app/` and fails on any `.replace(/</g` shaped call in code, so the next person cannot reintroduce a second partial one without the gate saying so.
- **Modular providers (native vtable)** — a provider is now one file implementing a `Provider` vtable (`buildRequest` / `parseResponse` / `parseErrorDetail` / `parseStreamEvent` / `authHeaders` / `endpointUrl`, `src/llm/providers/api.zig`) plus one row in the registry table in `src/llm/registry.zig`. `src/llm/providers/{openai,anthropic,vertex}.zig` hold each provider's wire codec, auth strategy and transport quirks together; vertex re-exports anthropic's codec rather than copying it, and the two differ only in a body header, the URL verb and the credential. Streaming went through the same split: each provider's `parseStreamEvent` is a pure `(chunk_arena, payload) -> ?StreamEvent` function, and one `StreamAccumulator` in the core folds both the OpenAI `choices[].delta` vocabulary and the Anthropic `content_block_delta` one into a `ChatResponse`, so the two token accounting paths can no longer drift. Behaviour-preserving: same wire bodies, same retry policy, same existing config keys. Each provider's codec is now unit-testable in isolation on the host, and the tests live beside it. Adding a provider is one file, one registry row and one `ProviderKind` tag (ADRs [0004](adrs/0004-providers-are-a-native-vtable-not-wasm.md), [0005](adrs/0005-auth-is-a-strategy-axis-separate-from-wire-kind.md)); Cursor's persistent HTTP/2 session ([docs/cursor-api-notes.md](cursor-api-notes.md)) would still need the transport core extended, which the vtable deliberately does not cover.

- **Blind side-by-side model comparison (`clanker compare`)** — the Odysseus gap below, closed. Decision on where the concurrency lives: [docs/adrs/0006-fan-out-concurrency-belongs-to-the-host.md](adrs/0006-fan-out-concurrency-belongs-to-the-host.md). One prompt goes to 2-8 configured provider/model targets at once and the answers come back as `A`, `B`, `C` with nothing saying which model wrote which; a judge model picks a winner, or `--judge none` leaves the pick to the human and `compare --show <id> --pick <letter>` records it. `--synthesize` merges the answers into one as an extra call. The split mirrors arena's: `tools/zig/compare_logic.zig` imports nothing from the guest ABI and is unit-tested on the host, `tools/zig/compare.zig` is the shell that resolves targets, makes the calls, persists and renders, and `cmdCompare` in `src/cli.zig` only builds the tool's input, so an agent calling the tool and a person typing the subcommand get one implementation rather than two. **The concurrency is a new host function, `ck_llm_many`**, not a loop in the guest: a wasm guest is single-threaded, so N models asked one at a time cost the sum of their latencies. The host fans the targets out one thread each and joins them all before returning, the same shape `ck_swarm` already uses for nested agents, so the batch costs the slowest model and the caller never sees a half-finished one. It carries the same `"llm": true` descriptor grant and charges the same session token budget a loop of `ck_llm` would have; one failing target is a failing element (with the provider's own error text attached), never a failing call, so a comparison of five models where one is out of credit is still a comparison of four. **Blindness is three separate mechanisms**, because any one of them alone leaks: the display order is a permutation seeded from the comparison id rather than the order the targets were configured in (stable enough to re-render a stored comparison, not the order a reader would otherwise correctly guess), the labels are positional and never derived from the provider, and each entrant's own provider/model names are struck out of its own answer before anyone reads it, since a model that opens "As DeepSeek, I would..." has un-blinded itself. The stored document is written in blind order too, so the file does not leak what the render withholds. **Deliberate non-goals**: this is not `providers check`, which pings for connectivity and latency and says nothing about answer quality, and it is not `arena`, where the models argue against each other over rounds and see each other's moves; here they answer once and never see each other. `judge = "auto"` resolves to `default_provider` rather than hunting for a provider that is not an entrant, because the guest cannot tell a configured provider from a reachable one and `config.toml` ships half a dozen stanzas most machines have no key for; when the judge is itself an entrant the verdict carries a caveat saying so, rather than the tool silently returning no verdict at all. **The web UI view shipped** (`ui/app/features/compare.js`, `GET /api/compare`, `GET|POST /api/compare/<id>`): the listing, the answers side by side in their stored blind order under nothing but `A`/`B`/`C`, and a pick button per column that posts to the same `compare` tool op `compare --show <id> --pick <letter>` calls, so a browser pick and a terminal pick are one recording path rather than two. What made it more than a rendering job: the tool's read-one and list paths were written for a caller who had already watched the blind view that minted the id, so both revealed unconditionally, and a browser has watched nothing. `"reveal": false` now says so, and it withholds the key from the *payload* rather than from the render, because a page that receives providers and declines to paint them is one devtools panel from being un-blinded; the ledger's winner column (a provider name, next to a verdict letter the blind view does show, which is the whole key for a two-way comparison) is withheld from an un-revealed listing the same way, leaving "judged" or "no verdict"; and a leak the new tests caught on the way is fixed, since the blind render named the judging provider beside the verdict while the caveat on the next line said that provider may also be an entrant. Reading one back is a read of `state/compare/<id>.json`, so it calls the tool directly and prints what comes back: putting a completion in that path would be slow, billed, and would hand a paraphraser a document whose entire point is that no entrant chose its wording — a summarizing model is one sentence away from naming who wrote answer B. (2026-08-13: done as `clanker compare` plus the `compare` tool and the `ck_llm_many` host function, synthesis included — see **Blind side-by-side model comparison** under Done. The web UI view followed on 2026-08-13 (Compare tab: blind side-by-side plus a pick button); the REPL `/compare` command shipped the same day — see **The REPL /compare command shipped** above..)
  - **No native recurring/scheduled agent runs.** (2026-08-13: done, see **Scheduled runs (`clanker schedule`)** under Done.) Odysseus ships scheduled agent tasks and CalDAV-synced reminders as first-class workspace features. Clanker has no analogous built-in — recurring runs today depend entirely on an external cron calling `clanker run`/`scripts/clanker-improve.sh`/`scripts/clanker-review.sh` from outside the binary (see those shell scripts). A `clanker schedule` subcommand (a `state/schedule.json` list of cron-like entries, checked by a lightweight always-on `serve` loop or a `clanker schedule run-due` invoked by the system's own cron) would remove that outside dependency, but is a genuinely new subsystem, not a small addition — worth a PRD before starting, not a same-session build.
  - **Not adopting, and why:** Odysseus's 2FA/multi-user auth doesn't apply to `clanker serve`'s *default* trust model — it binds `127.0.0.1` unless `[serve].host`, `CLANKER_HOST` or `--host` says otherwise (config < env < flag), and `unexpectedHost` in `src/cli.zig` refuses any `Host`/`:authority` that is not an IP literal at this port, `localhost`, or a name passed to `--serve-as`. So out of the box there is no network-facing surface to authenticate against. That is a default, not a guarantee: `serve --host 0.0.0.0` is unauthenticated too, and anyone who can reach the port gets full agent and tool access, so the access control there is a firewall or a trusted network, not clanker. Real multi-user exposure would need auth first, and remains a non-goal until it becomes an explicit one. Pi's own docs note it has *no* built-in permission system and runs with the user's full process permissions — the opposite direction from clanker's `ck_*`/descriptor sandbox, so this is a validation of the existing design, not a gap to close.
- **Feature audit vs. Feynman (2026-08-13)** — compared clanker against [companion-inc/feynman](https://github.com/companion-inc/feynman), Companion's open-source terminal research agent (TypeScript, built on Pi's agent runtime: the same Pi audited on 2026-08-12, so the harness layer is already covered; what is new here is the skill layer on top). Most of feynman's surface is domain research machinery out of scope for a coding/ops harness — PaperRank, alphaXiv paper Q&A, the bio-database tools (OpenAlex, PubMed, ChEMBL, UniProt, ...), literature reviews, replication planning — not adopting any of it. Four ideas are worth adapting:
  - **`/watch` — baseline plus scheduled follow-up.** Feynman's watch skill runs a baseline survey into `outputs/`, then registers recurring follow-up checks *if* a scheduler is reachable, and explicitly reports the capability as unavailable when it is not, rather than pretending monitoring exists. Clanker has the scheduler (`clanker schedule`) but an agent cannot reach it: the schedule entry under Done already names the missing WASM tool over `state/schedule.json` as its one open item. Watch is the feature that makes that tool worth building — a skill that runs the baseline (research_mode), saves it, and adds its own follow-up entry. Adopt in that order: schedule WASM tool first, watch skill second.
  - **Cross-session search.** Feynman's session-search skill: sessions are JSONL under `~/.feynman/sessions/`, `/search <query>` opens an interactive picker whose hits can be resumed, and the documented fallback is plain grep over the directory. Clanker's Ctrl-R searches the current transcript only; `state/sessions/` has no search at all. Adopt as `clanker session search <query>` (linear scan over the session store, print id + matching line, no index — the store is small), then a REPL entry that can resume a hit.
  - **Verifier pass with a provenance sidecar.** Feynman's outputs are source-grounded (claims carry direct URLs), deepresearch writes a `.provenance.md` sidecar beside the brief, and a dedicated Verifier agent checks citations and prunes dead links. Clanker's research_mode injects a search/fetch directive but nothing ever checks the citations in the answer. Adaptable as an opt-in post-run verify step: a subagent that fetches each cited URL via the existing `fetch_web` and flags dead or unsupporting ones. No new machinery — subagent + fetch_web compose it.
  - **Named agent role presets.** Feynman bundles four roles (Researcher, Reviewer, Writer, Verifier) as plain markdown prompts in `prompts/`, referenced by name from skills. Clanker's `subagent` tool takes only a free-text task; every skill that wants a reviewer-shaped subagent re-describes one. Cheap adoption: role prompt files under `docs/prompts/` that skills and the subagent tool reference by name.
  - **Not adopting, and why:** skills-only installers into other harnesses (feynman can install just its skills into Claude/Codex/OpenCode trees; clanker's skills name clanker's own tool vocabulary, so exporting them exports calls nothing else can make); the standalone bundle with pinned Node.js and SHA-256 release verification (clanker is one static Zig binary — no runtime to pin); local-model `/v1` endpoints (already have, multi-provider client); feynman's own autoresearch skill (same hypothesis→measure→retain shape as clanker's shipped generic loop; the only takeable detail is its narrative `autoresearch.md` sidecar beside the structured ledger, noted here, not planned); `/jobs` visibility (mostly covered by `clanker schedule list|log` + `clanker graph`; a unified "what is running or scheduled" view can wait until something is actually confusing).
- **Feature audit vs. deepseek-code.com / DeepSeek Harness (2026-08-14)** — the user asked to review [deepseek-code.com](https://deepseek-code.com), whose own footer discloses it plainly: "an independent informational website, not an official DeepSeek website," an SEO-style guide/aggregator (FAQ boilerplate, affiliate-shaped "guides" like "5 Best DeepSeek Harness Alternatives") that indexes a GitHub `dsh-plugin` topic. It is not the source itself. Six ideas were concrete, well-specified by DSH's own docs, and genuinely missing here — two of them close gaps `docs/reviews/webui.md`'s own Kimi Code parity table already named in writing ("ACP/IDE integration," "MCP client configuration," "lifecycle hooks"):
  - **Lifecycle hooks.** DSH's `packages/hooks/` bridges an existing Claude Code `hooks.json` onto typed extension points, with a dialect-neutral core (matcher validation, exit-code/JSON-stdout decode, most-restrictive merge) shared between Claude Code and Codex dialects. Clanker has the analogous gate already (`plan_mode`/`confirm_fn` in `Agent.executeCalls`) but nothing that can run an external policy script. PRD: [docs/prds/0028-hooks-bridge.md](prds/0028-hooks-bridge.md).

PRD: [docs/prds/0029-loop-hygiene-guard.md](prds/0029-loop-hygiene-guard.md).
  - **ACP server.** DSH's `packages/acp/` is a minimal, automation-only [Agent Client Protocol](https://agentclientprotocol.com) server — the protocol Zed and other editors use to embed an external coding agent. Clanker already serves MCP (`clanker mcp`); this is the same shape for ACP. PRD: [docs/prds/0030-acp-server.md](prds/0030-acp-server.md).
  - **Deterministic tool-result pruning.** DSH's `compaction-tool-result-pruner` rewrites one oversized tool result to a bounded head/marker/tail with no LLM call, cheaper than clanker's existing LLM-summarization compaction path for the common case of one bulky result dominating the budget. PRD: [docs/prds/0031-tool-result-pruning.md](prds/0031-tool-result-pruning.md).
  - **MCP client bridge.** Clanker only serves MCP today; DSH's `mcp-client` package shows the wire contract for consuming external MCP servers (server-qualified tool naming, reconnect/backoff). The named trade-off: an MCP server sits outside clanker's WASM sandbox entirely, the same trust level Claude Code's and Codex's own MCP client config already asks users to accept. PRD: [docs/prds/0032-mcp-client-bridge.md](prds/0032-mcp-client-bridge.md).
  - **Agent presets.** DSH's `agent-presets`/`persona` packages compose a named tool allowlist plus persona text per session. Supersedes the cheaper "role prompt files" note from the 2026-08-13 Feynman audit above, which only ever changed what the model was *told*, never what it could *call*. PRD: [docs/prds/0033-agent-presets.md](prds/0033-agent-presets.md).

- **TTSR (time-traveling stream rules)** — regex match on the LLM's streaming output aborts the stream mid-token, injects a rule as a system message, and retries from the same point. Zero tokens spent on the rule until a match fires; injections survive compaction. Lives in `src/agent/loop.zig` + a new stream-interception layer. PRD: [docs/prds/0013-ttsr.md](prds/0013-ttsr.md).
- **Hashline edit format** — hash-anchored line edits: `read_file` annotates lines with 4-hex xxHash32 digests; `edit_file` anchors by hash rather than exact text; the host rejects stale patches before writing. omp benchmarks: -61% output tokens on Grok 4 Fast, pass@1 from 6.7% to 68.3% on Grok Code Fast. PRD: [docs/prds/0014-hashline.md](prds/0014-hashline.md).
- **Advisor** — a second model reads every completed turn and injects a severity-tagged note (`note`/`concern`/`blocker`) at the top of the next turn. Blockers pause the loop for human confirmation. Configured via `[advisor]` in `config.toml`; disabled by default. PRD: [docs/prds/0015-advisor.md](prds/0015-advisor.md).
- **Eval kernel** — persistent Python subprocess and optional Bun worker kernels, session-scoped, with state across calls. A loopback HTTP bridge lets kernels invoke any registered WASM tool by name. Supports `%pip`, `%time`, `%%bash`, and `!cmd` magics. PRD: [docs/prds/0016-eval-kernel.md](prds/0016-eval-kernel.md).
- **DAP (Debug Adapter Protocol)** — drives real debuggers (`lldb-dap`, `dlv`, `debugpy`) via the DAP JSON-RPC protocol over stdio. Operations: `launch`, `attach`, `set_breakpoints`, `continue`, `step_in`, `step_out`, `next`, `pause`, `stack_trace`, `scopes`, `variables`, `evaluate`, `disconnect`. Gated by `debug.enabled` in config. PRD: [docs/prds/0017-dap.md](prds/0017-dap.md).
- **Snapcompact** — replaces the LLM summarizer in the compaction path with a deterministic pixel-font PNG renderer. The model reads back the image instead of a summarizer's prose. No LLM call, no hallucination risk, approximately 1/3 the token cost of LLM summarization. Requires a vision-capable model. PRD: [docs/prds/0018-snapcompact.md](prds/0018-snapcompact.md).
- **GitHub filesystem** — extends `read_file` to accept `gh://` URL schemes: issues, PRs, PR diffs, and issue list queries. SQLite cache with soft and hard TTLs and background refresh. Requires `GITHUB_TOKEN`. PRD: [docs/prds/0019-github-fs.md](prds/0019-github-fs.md).
- **Auto thinking** — a per-turn classifier call (small fast model) resolves the reasoning effort level (`low`/`medium`/`high`/`xhigh`) from the user's message text. Cheap turns stay cheap; complex turns get the budget. Override applies to the main think call only; opt-in via `agent.auto_thinking = true`. PRD: [docs/prds/0020-auto-thinking.md](prds/0020-auto-thinking.md).
- **Smart commit** — `clanker commit` reads the working tree diff, calls the LLM to group hunks into atomic commits, topologically sorts them by file dependencies, orders source before tests/docs/config, validates conventional commit types, and executes in order. Lock files excluded; cycles rejected. PRD: [docs/prds/0021-smart-commit.md](prds/0021-smart-commit.md).
