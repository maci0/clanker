# PRD — TTSR (Time-traveling stream rules)

## Status

Draft. No source files yet. Feature lives in `src/agent/loop.zig` (the streaming
path) and a new `src/agent/ttsr.zig` for the rule engine. Config lives in
`config.toml` under a `[ttsr]` section.

## Problem

The agent loop (`src/agent/loop.zig`) streams LLM output token-by-token and
passes the full completion to tools after the stream ends. There is no way to
inspect the partial stream as it arrives and intervene before the model finishes.
This matters when the model is about to do something wrong that a simple pattern
could detect early: it costs the full completion's tokens, and the correction
(if any) comes in the next turn, burning another full context's worth of
re-reasoning.

omp's TTSR (time-traveling stream rules) aborts the stream the moment a regex
fires, injects a rule into the system context, and retries from the same point,
so zero tokens are spent on the rule until a match happens. The rule survives
context compaction, so it keeps applying. Clanker has no equivalent: once a
stream starts, it runs to completion regardless of what comes out.

## Goals

1. A stream-intercept layer in the agent loop that applies ordered
   literal/substring rules (with optional `*` wildcards) to the partial token
   buffer as bytes arrive and can abort an in-flight stream.
2. On match: the stream is torn down, the rule's injection text is appended to
   the system message, and the turn retries from the top of the think-act-observe
   cycle with the same user message.
3. Rules survive compaction: they live in the system context, not in conversation
   history that `maybeCompactMessages` can trim.
4. Rules are declarative: defined in `config.toml` under `[[ttsr.rules]]`, each
   with a `pattern`, an `inject` string, and an optional `max_fires` count
   (default 1). Patterns are literal/substring match with optional `*` wildcards
   (not full regex); no in-process regex engine is required.
5. Rule firings are logged to `state/ttsr.jsonl` with the matched token offset
   and the rule name, so they are auditable after a run. `max_fires` is counted
   per session; the jsonl file is audit-only and does not drive the counter.
6. A per-turn retry budget (`ttsr.max_retries_per_turn`, default 3) caps how many
   TTSR aborts-and-retries a single turn may perform, independent of any rule's
   `max_fires`.

## Non-goals

- Not a general output filter. Rules only abort-and-retry; they do not rewrite
  or suppress model output in place. Post-processing belongs to transforms
  (the existing `after`/`before` chain).
- Not real-time per-token semantic analysis. Patterns are literal/substring (with
  optional `*` wildcards) against byte buffers, not embeddings, classifiers, or
  full regex. Expensive semantic checks belong in the advisor (PRD 0015), not here.
- Not a firewall for harmful content. Rules are developer-defined, not a content
  policy layer. Misuse of `max_fires = 0` (which would loop forever) is refused
  at load time, not a safety mechanism.
- Not retrying with a different model. The retry uses the same provider and model.
  Provider fallback is a separate concern.
- Not a post-turn critic. TTSR fires during a stream and aborts it; the advisor
  (PRD 0015) fires after a completed turn and only annotates the next one.
  Different interception points, deliberately.
- Not an ephemeral host-function API in v1. `ck_ttsr` (WASM tools registering
  rules for one tool call) is deferred to Phase 2 pending an ADR under ADR 0006
  (ABI growth). v1 is config rules only.

## Design

**Match engine (decided).** Patterns are literal/substring match with optional
`*` wildcards that span any byte sequence (including empty). No full regex. Examples:

| Pattern | Matches |
|---|---|
| `rm -rf /` | Exact substring `rm -rf /` |
| `git push*--force` | `git push` … anything … `--force` |
| `FIXME:` | Exact substring `FIXME:` |

`*` is the only metacharacter. To match a literal `*`, escape as `\*`. Invalid
escape sequences fail at load time with the rule name and pattern in the error.
Compilation is a one-time convert-to-automaton (or equivalent) at startup, not
per chunk.

**Rule schema (config.toml).**

```toml
[ttsr]
max_retries_per_turn = 3
buffer_bytes         = 4096

[[ttsr.rules]]
name      = "no-rm-rf"
pattern   = "rm -rf /"
inject    = "Never emit destructive shell commands without a dry-run flag."
max_fires = 3

[[ttsr.rules]]
name    = "no-force-push"
pattern = "git push*--force"
inject  = "Prefer --force-with-lease; state why a force push is necessary."
```

Rules are applied in declaration order. There is no `priority` field in v1; on
multiple matches in one chunk, the first rule in declaration order wins.

**`max_fires` (decided: per-session).** Limits how many times a single rule may
fire within the current clanker session. At the limit, the rule is silently
disabled for the rest of the session and a warning is written to the log.
`state/ttsr.jsonl` is an audit log only; it does not persist or restore the
fire counter across sessions. A new session starts every rule at zero.

**`max_retries_per_turn` (decided).** Independent of `max_fires`. Caps abort-
and-retry cycles inside one turn (default 3). When the budget is exhausted, the
turn proceeds to completion without further TTSR aborts for that turn, even if
matching rules remain enabled.

**Non-streaming providers (decided).** If rules are configured and the active
provider/model has `stream: false`, clanker logs a startup warning that TTSR
will have no effect. It does not refuse to start or refuse to register rules.

**Stream interception.** The streaming path in `Agent.run` feeds tokens through
`client.chatStream`'s `on_token` hook. TTSR wraps this hook with a
`StreamGuard` (new type in `src/agent/ttsr.zig`) that:

1. Appends each chunk to a ring buffer (configurable via `ttsr.buffer_bytes`,
   default 4096).
2. After each append, runs the compiled pattern set against the tail of the buffer.
3. On the first match (declaration order), signals the stream to abort (sets the
   existing `stop_flag`, which `chatStream` already checks per chunk).
4. Records the match to `state/ttsr.jsonl`.
5. Returns the matched rule to the caller.

The ring buffer keeps only the tail so long runs don't accumulate. Pattern
compilation happens at startup (or on first use), not per token.

**Retry mechanics.** When `StreamGuard` returns a matched rule, `Agent.run`:

1. Discards the partial assistant message from `session.messages` (it was not
   added to history yet, since history is only appended after a complete turn).
2. Appends the rule's `inject` text to the system message as an injected block
   tagged with `[ttsr:<name>]`.
3. Increments the per-turn retry counter; if it would exceed
   `max_retries_per_turn`, skips the abort path and lets the stream finish.
4. Re-enters the turn loop from the top. The user message is unchanged; the
   injected rule is now visible.

The system message injection is append-only per rule name; a rule that fires
twice does not duplicate its block.

**Compaction survival.** `maybeCompactMessages` trims `session.messages` (the
conversation history), not the system prompt. Injected rule blocks live in the
system prompt, so they survive compaction without any special handling.

**`ck_ttsr` (deferred).** Host-function registration of ephemeral rules is out of
scope for v1. It requires an ADR under ADR 0006 before any ABI growth. When
added later, the guest would write a JSON payload and the host would register
the rule for the current tool call's duration only.

**`ck_stats` integration.** The existing stats pipeline records TTSR fire counts
per session alongside token counts, so `clanker stats` shows rule firings and
`GET /api/stats` exposes them.

**Dependencies.**

- Agent streaming path in `src/agent/loop.zig` (`chatStream` / `on_token` /
  `stop_flag`). TTSR is a wrapper around that hook; non-streaming providers are
  warned, not blocked.
- Config parser (`src/config.zig`) for `[ttsr]` and `[[ttsr.rules]]`.
- Stats / jsonl append path used by other session audit logs (`state/*.jsonl`).
- Soft boundary with PRD 0015 (advisor): different interception points (during
  stream vs after turn). No shared code required in v1.
- Soft boundary with ADR 0006: `ck_ttsr` blocked until an ABI-growth ADR lands
  (Phase 2).

**Implementation.**

1. **`src/agent/ttsr.zig`**: pattern compiler (literal + `*`), ring buffer,
   `StreamGuard`, per-session `max_fires` counters, per-turn retry budget.
2. **Config**: parse `[ttsr]` / `[[ttsr.rules]]`; validate patterns and refuse
   `max_fires = 0` at load; warn when rules are present and `stream: false`.
3. **Loop integration**: wrap `on_token` with `StreamGuard`; on match, inject
   into system prompt and retry within `max_retries_per_turn`.
4. **Audit + stats**: append firings to `state/ttsr.jsonl`; expose
   `ttsr_fires` via `clanker stats` / `GET /api/stats`.
5. **Phase 2 (later)**: ADR under ADR 0006, then `ck_ttsr` ephemeral host
   function. Not part of v1 acceptance.

## Failure modes

| Condition | Behaviour |
|---|---|
| Pattern validation fails at startup | Fatal: clanker refuses to start; logs the offending pattern and rule name |
| Stream aborts but the LLM endpoint returns an error on the teardown | The partial message is discarded; the retry proceeds as normal; the abort error is logged at debug level |
| Rule fires, retry fires the same rule again immediately | Counted against `max_fires` and `max_retries_per_turn`; at either limit the abort path stops for that rule/turn; if every rule is disabled and the same pattern keeps appearing, the turn proceeds to completion (no infinite loop) |
| `max_retries_per_turn` exhausted | Turn proceeds without further TTSR aborts; remaining enabled rules stay enabled for later turns |
| Rules configured with `stream: false` | Startup warning only; rules stay registered but never fire |
| `ttsr.buffer_bytes` too small to catch a multi-token pattern | Pattern simply does not match; no error. Document minimum buffer sizing in the manifest |

## Acceptance criteria

- [ ] `ttsr.rules` parsed from `config.toml`; invalid patterns (bad escapes,
      empty name) cause a startup error with the rule name and pattern in the
      message.
- [ ] Pattern match is literal/substring with optional `*`; unit tests cover
      exact match, wildcard span, and `\*` escape.
- [ ] `StreamGuard` intercepts an in-flight stream, fires a matching rule, and
      the turn retries with the injection visible in the system prompt.
- [ ] A rule that fires during a retried turn increments the fire counter; at
      `max_fires` the rule is disabled for the session and the turn proceeds
      without aborting on that rule.
- [ ] `ttsr.max_retries_per_turn` (default 3) stops further aborts within a
      turn independently of `max_fires`.
- [ ] Injected rule blocks survive a `maybeCompactMessages` call (verify by
      asserting the system prompt before and after compaction).
- [ ] Multi-match in one buffer uses declaration order; no `priority` field.
- [ ] Startup warns (does not refuse) when rules are configured and streaming
      is disabled.
- [ ] `state/ttsr.jsonl` contains one entry per firing with rule name, turn
      index, and matched byte offset; counters reset per session.
- [ ] `clanker stats` includes a `ttsr_fires` column; `GET /api/stats` exposes
      the same count.
- [ ] Unit tests in `src/agent/ttsr.zig` cover: wildcard match on a partial
      buffer, ring-buffer tail behavior, `max_fires` enforcement, and
      `max_retries_per_turn` exhaustion.
- [ ] `ck_ttsr` is not part of v1 (deferred; no host function shipped).

## Open questions / future work

- **Richer pattern dialects.** Character classes or alternation could be added
  later if literal+`*` proves too weak; that would be a new decision, not a
  silent expansion of v1.
- **`ck_ttsr` host function.** Phase 2 after an ADR under ADR 0006; v1 ships
  config rules only.
