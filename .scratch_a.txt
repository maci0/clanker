- `src/agent/` — agent loop, system prompt assembly, session store, workspace registry (`workspace.zig`: project id over one or more named roots + chat-history set; empty id = serve cwd; ids reject `/`, `\`, `:` so `ws:<id>:goal:<id>` room namespace stays unambiguous, RFC 0001), execution graphs, sub-agents, autolearn, workflows. Auto-thinking classifier prompt/parse/effort map in `tools/zig/thinking_logic.zig` (host-tested); `thinking.zig` keeps provider resolution + fail-open `client.chat`; `thinking` guest same classify via `ck_llm`. `agent.reasoning_effort` (CLI `--reasoning-effort` on repl/run/goal) pins per-turn effort ahead of the classifier; the pin rides `ChatParams.reasoning_effort`, top of `writeSamplingParams` precedence (params > per-model config > sampling profile). The completion grant is the model's `max_tokens` (`turnCompletionBudget`), never `agent.max_tokens_per_turn` — that knob is the per-turn input/compaction floor, and sending it as `ChatParams.max_tokens` spent a reasoning model's 4096 grant on `reasoning_content` (run-1787011404). Autolearn recording stays native (every tool call/run); `autolearn` guest owns roadmap upsert and optional `--model` rewrite via `ck_llm`. Session ids are path fragments; every CLI/TUI/HTTP entry uses `session.zig` `validSessionId`, and every surface that starts a new conversation mints one through `session.mintSessionId` (the REPL used to spell its own startup id `repl-<seconds>` beside the `sess-<nanos>` it minted on save). `listSessions`/`--continue` read only listing header (`message_count`/`bytes` before `messages`); pickers must not parse every transcript. `GET /api/sessions` relays `sessions` guest (`format=json`); `GET /api/sessions/search` is the same guest with `q`; mutations + full transcript stay native. `GET /api/providers` relays `providers` guest (`action:list`); live `/models` fill for empty map stays native (credentials), and usability annotation is native too (see `src/serve/`). Session search scores same header, then opens transcripts newest-first, stops at page limit. `graph` and `knowledge` guests use `ck_fs_read_range` — full `ck_fs_read` per file burns 1 MiB arena and drops later rows (`sessions` asks the host store through `ck_session`, so the arena is never its problem). Knowledge listing scalars (`doc_count`, `bytes`) before `docs`. Graph listing reads 4 KiB prefix (scalars before `task`/`nodes`), caps picker at 50 newest runs; 48 KiB × dozens of files used to exhaust arena mid-list. `state/runs/` writes both spellings in nanoseconds (`run-<ns>` here, `sub-<ns>` in `subagent.zig`), and graphs older than that are `run-<seconds>`, so newest = `graph_listing.lessThanChronological`, which pads the digits to one width, not filename sort — `sub-` > `run-` lexically, so filename sort filled newest page with oldest sub-runs. A run graph's `provider` is stamped in the persist defer from `self.provider` at exit, not only at start: `chatWithFallbackChain` repoints it to whoever served, and a start-only stamp recorded a provider that never answered (run-1787063448). It also carries `agent.seed`, before `task` so the listing prefix keeps it: a failed run names the seed that re-runs it (`ckRandom`'s log line only exists if a tool drew, so a run that failed before its first tool call recorded nothing to replay with), and 0 means time-seeded, so not reproducible. `Agent.on_token` has no context arg, so streaming side-state (`stream_tally`, TTSR guard, `run_stream_socket`) is threadlocal; process-static would splice concurrent `/api/run` streams. `ttsr.buffer_bytes` clamped to `ttsr_buffer_bytes_max` (window allocated from run arena each LLM turn). History sent to model is append-only. DeepSeek rule: "model-visible means logged" — session is event log, next request *derived* from it, sent prefix never rewritten (mutating busts provider prompt cache). Compaction/prune/inject must project request-only copy (`requestMessages`/PRD 0031) or append replacement. Don't edit/delete saved message already sent. `session.compactMessages` and `loop.maybeCompactMessages` still rewrite in-memory list; existing exceptions, not pattern. New model-visible input (system-prompt section, inject, tool result) must land in saved session, not just wire. Harness *framing* around a user's words is the exception, and only when re-applied deterministically: a steer message stores the user's words plus `Message.steered`, and `applySteerFraming` puts `steer_frame_sentence` on the request copy every turn (same bytes after a reload, so the prefix never changes). Framing it at the sender saved the harness's sentence as the user's own first line. Not a mid-conversation `.system` message: `anthropic.zig`/`gemini.zig` hoist those into the top-level system field, detaching the framing from what it frames. Session store is SQLite with `CREATE TABLE IF NOT EXISTS`, so a new `messages` column needs a row in `added_message_columns` too (ALTER on every open, duplicate-column error swallowed) — schema alone leaves every existing session without it and every read of it fails. sqlite3_open_v2 creates the file with the process umask, so `Connection.open` chmods the database and its `-wal`/`-shm` sidecars to 0600 after the WAL pragma (the same owner-only mode `atomic_write.private_file` uses for JSON stores); a trim of `state/reasoning.jsonl` that writes with default create permissions drops that mode. Request-only prune persists omitted middle under `state/spills/<session>/` and leaves `[spill id=........]` locator on request copy; `spill` guest writes/reads file (loop decides which messages to spill, appends locator after guest confirms write). Deleting a session must take that conversation's text with it: `DELETE /api/sessions/<id>` also calls `spill` `forget` and `session_export` `forget`, because `state/spills/<session>/` and `state/exports/<id>.html` hold the same text under the session's own name and janitor deletes nothing on its own (ADR 0008). A new per-session store needs its own forget op on the guest that owns the path. A shared store needs the same treatment keyed by session, which is why a reasoning record carries one and `Agent.forgetReasoningForSession` rewrites `state/reasoning.jsonl` dropping that session's lines: each holds the user's task text and a model trace quoting it, so without the key the log is one pool of every conversation the harness has ever run, none of it erasable. A line that will not parse, or one predating the field, is kept, since neither can be attributed. The parallel `ToolWorker` builds its sandbox through `host.sandboxFor` (the single source of truth) and adds only the agent extras it knows about — a hand-rolled `Sandbox` literal there drifted four times (`exec_allow`/`env_allow`, `tool_self_name`, `session`) and each drift silently denied a parallel-run tool a capability the sequential path granted, the `session` one failing the `session_search` capability eval and stopping improve-self.
