# clanker — project conventions

clanker is a self-improving AI agent harness in **Zig 0.16.0**; tools run as sandboxed WASM (zwasm) and it improves its own source via a gated loop.

## Build & test

- `zig build` — build the host (musl on Linux). Cross-compile: `-Dtarget=x86_64-linux-musl`. Optimize mode is Zig's default, **Debug**, and `zig-out/bin/clanker` is that build, so never profile it: a scalar byte loop LLVM turns into 1.5 GB/s in ReleaseFast reads as 44% of `clanker stats` under Debug, and the wasm interpreter (also built Debug, see `zwasm_dep` in `build.zig`) swamps everything else. `-Doptimize=ReleaseFast` before `perf`/`hyperfine`, or measure the one function in a standalone ReleaseFast harness.
- `zig build tools` — compile `tools/zig/*.zig` → `zig-out/tools/*.wasm`.
- `zig build test` — unit + integration tests; must pass before any change. Tests live in `test` blocks. New `src/` modules must be referenced from `comptime` in `src/main.zig` or tests don't run. Pure `tools/zig/` helpers (no guest ABI) go in `host_tested_helpers` in `build.zig`; WASM guests can't run `test` blocks. `-Dtest-filter="<substring>"` compiles only the matching Zig tests in (compile-time filter, Zig 0.16 dropped the runner's runtime filter) — a tight loop for one `test` block; a filter matching nothing passes with 0 tests, and the node `--test` suites always run (run one directly: `node --test <file>`).
- `zig build e2e` — black-box E2E against mock LLM server. Not part of `zig build test`; run separately.
- `zig build run` — build and run in one step.
- `zig build proxy` — build `clanker-proxy` (OpenAI/Anthropic compat) standalone (no web UI, agent, TUI, tool host). Not in default install.
- `clanker gate` — runs build, test, tools, fmt, lint, provider-kind, test-root-coverage, sandbox-abi, tools-ts-toolchain, release-contract gates. `sandbox-abi` pins that every `pub fn ck…` in `src/sandbox/host.zig` is registered with the zwasm linker in `src/sandbox/runtime.zig`; an unregistered one is unreachable by any guest, so it rots against zwasm API changes in silence. `test-root-coverage` is the one gate a green suite cannot substitute for: Zig 0.16 runs `test` blocks only in the root file, so a `src/` module missing from the comptime block in `src/main.zig` has tests that silently never run. Release policy/version: [RELEASES.md](RELEASES.md); visible changes: [CHANGELOG.md](CHANGELOG.md). Drops `.zig-cache` over size limit, so gate after long session rebuilds from scratch and takes minutes longer; that log line is the cause, not a stall.
- A `zig build test` step failing with no test named is usually tree moving under build (concurrent edit or competing test binary), not a defect: re-run or run `.zig-cache/o/<hash>/test` directly.
- Read Zig's exit code directly, never via pipe. Improve/gate tests run nested build in staging copy, so passing run still ends with `failed command: ./.zig-cache/o/<hash>/test --listen=-` and `capability gate failed: no staged binary` — lines mean assertion succeeded, not suite failed. `zig build test 2>&1 | tail` reports `tail`'s 0. Two sessions misread same green run as red.

A pty e2e that asserts on screen *text* must force a full repaint (resize by one row) after the keystrokes and match with spaces stripped from both sides: vaxis diffs cell-by-cell, so a changed row reaches the stream as fragments and blank cells are cursor-jumped rather than written (`tests/e2e/pty_preview_test.zig` is the pattern; shared pty plumbing in `tests/e2e/pty.zig`).

Write failing test first, beside shipped function (`test` in `src/`, `host_tested_helpers` for pure `tools/zig/`, `tests/e2e/` for operator verbs). Confirm it fails for intended reason (wrong answer, missing file, refused path), not missing import from `src/main.zig`/`tests/e2e/main.zig`. Then implement to green. Don't add helpers only called by tests — that's inert, not TDD. Passing test must drive real entry and assert shipped output (stdout, JSON field, file). Re-implementing logic in test, injecting finished result and reading it back, or checking only exit 0 is not a test. Non-trivial logic and untrusted-input parsers need tests (fuzz parsers); trivial wrappers don't. Prefer unit for pure functions, E2E for CLI/HTTP journeys.

## Zig style

- Target Zig 0.16: `std.Io` (Dir/File/Threaded), `std.process.Init`, `std.json.Stringify`+`parseFromSliceLeaky`, `std.ArrayList` with `.empty`+`append(alloc, ...)`. `@intFromFloat` is `@trunc`/`@floor`/`@round` with integer dest; `@trunc(opt orelse 800)` treats default as comptime_float, so bind `f64` first. `@intCast` of `jsonInt` → `u32`/`u64` wraps negatives in ReleaseFast (`max_tokens=-1` became 4G cap); use `jsonUnsigned` for unsigned config ints.
- No libc beyond what build links.
- Allocators explicit: arena for run-scoped data, gpa for ownership.
- New code must be `zig fmt` clean (improve gate auto-formats and checks).
- Closed name tables: `std.StaticStringMap.initComptime` (`log.Level.fromStr`); `stringToEnum` can't alias `"error"` to `error_`.

## Architecture

- `src/llm/` — `client.zig` is shared HTTP/SSE/retry/token-counting core, one module per provider. `cache_cold` stamps last cache-accounted success per provider/model in process memory (ADR 0035); `recordUsage` calls `afterUsage` before the `modules.token_stats` guard so turning stats off does not skip the idle clock. `chatStream` retries same 429/5xx/transport as `chat` before any token, honoring `Retry-After` (int seconds, capped 30s). `agent.fallback_providers` walked by `chatWithFallbackChain` in `src/agent/loop.zig` after same-provider retries exhaust with no content; unknown names and providers `unconfiguredReason` rejects (missing key, empty URL) are skipped — the same offline gate as TUI `/model` — so a DeepSeek `ReadFailed` no longer spends a turn on `openai` and dies `MissingApiKey`. `cli.zig` vision swap stays pre-emptive, separate. Retries can't save a *hang*: `std.http.Client` has no read timeout and cancel can't reach a thread blocked on an established connection, so a provider that accepts and goes quiet returns no error to classify and the run never ends. Both branches of `chatWithFallbackChain` therefore run under `agent.request_timeout_ms` (whole non-streaming call, or first bytes of a stream) and `agent.stream_idle_timeout_ms` (gap between reads), via `chatWithTimeout`/`chatStreamWithTimeout`; `Abort` `shutdown(2)` is what unblocks the read. `Timeout` goes straight to the fallback chain, never retried on the same silent endpoint. Arm the first-byte clock even when streaming: `readSliceShort` returns only on a full 8 KiB buffer or end of stream, so a stream dying under one buffer never completes a read and is indistinguishable from one that never started. The *watchdog* goes on the `io.concurrent` worker and the request stays on the caller's thread — `on_delta` reads three threadlocals (`stream_tally`, `ttsr_guard`, `cli.zig` `run_stream_socket`) and log context is a fourth, so streaming from a worker silently stops rendering tokens and blinds the TTSR guard. `chatWithTimeout` (thinking/advisor) does move the request and is fine there: no callback. `[advisor]` is fail-open post-turn critique (off by default), distinct from `improve.arena_advisory`. Parse/summarize/inject in `tools/zig/advisor_logic.zig` (host-tested); `advisor.zig` keeps fail-open `client.chat`; `advisor` guest same review via `ck_llm`. Each provider is a vtable (`providers/api.zig`) in `providers/<name>.zig`, listed in `registry.zig`; `auth.zig` is credential acquisition, `gcp_jwt.zig`/`vertex_token.zig` Vertex minting (service-account JWT or gcloud ADC `authorized_user`, no subprocess). Adding provider = one file + one registry row + one `ProviderKind` in `config.zig` — never `switch (provider.kind)`. `provider-kind` gate in `src/gate/checks.zig` scans for kind-switches/comparisons outside `src/llm/providers/` and fails `clanker gate`; proxy's Vertex Gemini model-name sniff is the sole allowed comparison (on model name, not kind). Proxy reads `Provider.proxy` (family, speaks, enabled, chat-only, vtable URL, Vertex body rewrite, Anthropic header overlay); `auth.Spec.quota_from_project` is Vertex quota header.
- `src/sandbox/` — zwasm wrapper + `ck_*` host functions + policy. The tool-RNG seed is logged: `ToolModule.load` prints the effective `seedRng` value at info when `agent.seed` is 0 (time-seeded), so a run is replayable by setting `agent.seed` to the logged value, and `clanker eval --seed <n>` pins it for the evals. Privileged channels (`ck_docker`, `ck_kernel`, `ck_debug`, `ck_subagent`, `ck_swarm`, `ck_job`, `ck_stats`, `ck_ask`, `ck_std_api`, `ck_harness_config`, `ck_chat`, `ck_publish`) check `tool_self_name`; import ≠ grant. `ck_job` is jobs+subagent only (start-and-forget; `ck_exec` stays synchronous), implemented by `sandbox/jobs.zig` beside its channel; a `start` argv is gated by the same `execAllowed` allowlist and deny tokens as `ck_exec`, and the child gets the envAllowed-filtered environment, never the harness's own (a job process must not hold API keys the guest could not read). `ck_publish` also requires `"live_publish": true`, lands only on `Topic.plugin` (host stamps `t`/`from`). `ck_kernel` requires `kernel.enabled` and is implemented by `sandbox/kernel.zig` (the channel's code sits with the channel; only the session-keyed process table stays in `agent/subprocess.zig`, shared with DAP); `ck_debug` requires `debug.enabled`. Agent loop attaches subagent runner to every sandbox, so `ck_subagent`/`ck_swarm` otherwise callable by any guest. Structured config via `ck_harness_config`; `config` whole-file dump still reads `config.toml`/`config.local.toml` as raw bytes, so both names must stay on `fs_prefixes` (emptying breaks every dump as "config.toml unreadable"). Empty `env_allow` = safe defaults (PWD, HOME, PATH, …), never API keys; tools reading secrets via `ck_getenv` must name them. `.env` refused by `safeJoin`. `safeJoinSecure` refuses any granted path with symlink components, so a checkout where `state/` links to external storage denies all guest calls until `agent.sandbox_follow_symlinks` (ADR 0017); refusal blames `fs_prefixes` though manifest is correct. `ck_exec` allowlists git/zig/uv verbs, refuses host-absolute or `..` args, so guests can't bypass `network_allow`/`fs_prefixes` via subprocess. Config-injection and alternate-git-dir flags (`-c`, `--config-env`, `--git-dir`, `--git-common-dir`, `--exec-path`) are refused for sandboxed git by `gitExecDeniedArg`: `-c core.hooksPath=<dir>` executes hook scripts on commit (a guest can place a hook in its writable prefixes and commit), core.fsmonitor/core.sshCommand/core.editor/core.pager/credential.helper/diff.external spawn config-named programs (on git <2.43 alias.* could also shadow a builtin verb with a `!` shell command), and a fabricated `--git-dir` carries hooks that run on commit; `-C`/`--work-tree` stay (path-checked, single repo). A truncated exec result's `note` is a JSON string (`s.write`); `s.print` of the prose wrote raw text, so `repo_search` of a large hit set returned a blob the host warned was malformed JSON. Git's index verbs (`write-tree`, `read-tree` without `-u`, `restore` only with `--staged` and never `--worktree`) are allowed because `git add` and a pathspec `git commit -- <paths>` both take the *worktree* copy, so smart_commit can only honor a hunk-narrowed index by building the commit in the index; the worktree-writing forms stay denied like `checkout`. Search tools (`rg`, `ast-grep`, `semcode`) treat most args as patterns — `..` checked only on last arg. `ck_fs_find`/`ck_fs_grep` skip cache/vendor dirs (`zig-pkg`, `zig-out`, `node_modules`, `staging`, `history`, `__pycache__`, `.venv`, `.cache`) so project-root walks don't scan tree copies. Grep also skips binary/artifact extensions (`.map`, `.sqlite`). Both cap at 200 hits (paths/lines); `*` walks used to serialize all paths or fail `too_large`. `ck_fs_write_if` locks at `state/locks/<sha256-of-resolved-target>.lock` (ADR 0031), created via `ensureDir` since an isolated run's `state` is a symlink (`linkCheckoutStateAt`) while an improve worktree's is a real private directory by design (`linkSharedState` links only `improvements.jsonl` and `history`, on the rule that a symlink is safe only where the *host* reads the path — `safeJoinSecure`'s no-follow walk refuses a symlinked component to any guest). The lock dir resolves against `shared_root` either way, which is what keeps one lock inode per target across trees, and is allowed because locks are host-read: `casLockPath` never goes through `safeJoin`. it used to sidecar `<target>.ck_cas.lock`, which is why `docs/` collected one permanent zero-byte file per record. Hash the *resolved* target, never the joined string: one file is `./state/goals.json` under the default `sandbox_root` and `/abs/checkout/state/goals.json` under an isolated run's `shared_root`, so a string key gave each spelling its own lock and neither writer excluded the other. Resolve the directory part only — the target need not exist yet. The lock *directory* resolves against the run's own root (`shared_root` when set), not the process cwd: it followed cwd while the target followed the sandbox root, so test sandboxes wrote 328 of the 387 files in the real `state/locks`. A lock file is never unlinked while held — unlinking moves the lock to an unreachable inode and a second process locks a fresh one at the same name — but nothing has to reclaim it either: an `flock` dies with its descriptor, crash included, so a held lock is never stale and a heartbeat would guard nothing. `src/util/run_lock.zig` is the contrast, a *pid file*, reclaimed by probing the owner with signal 0. The lock file carries a fixed-width holder record (`tools/zig/cas_lock_record.zig`, shared with the `janitor` guest that ages them out at 12h); it names the *last* acquisition, so only `flock -n` answers whether one is held now. `ck_fs_write_if` runs that sweep itself (`sweepAgedLocks`, ≤1 pass/hour paced by `state/locks/.swept`, ≤512 deletes), because `janitor` deletes only on `--yes` and nothing fires on its own (ADR 0008) — the write that makes the garbage clears it. Age never licenses the delete: a candidate is opened `lock_nonblocking` and skipped on `WouldBlock`, and the unlink happens *while holding* the lock. Window is `cas_lock_record.keep_ms`, read by both sweepers. A *recordless* (zero-byte) lock file ages on its mtime instead, since `agedOut` answers "unknown, so not old" with no timestamp to read and nothing would ever sweep it; zero length is narrower than "unparseable" on purpose — a non-empty record that will not parse is still never swept, and neither is a negative stamp: subtracting it would overflow the age check, so it reads as unknown, not old.
- `src/agent/` — agent loop, system prompt assembly, session store, workspace registry (`workspace.zig`: project id over one or more named roots + chat-history set; empty id = serve cwd; ids reject `/`, `\`, `:` so `ws:<id>:goal:<id>` room namespace stays unambiguous, RFC 0001), execution graphs, sub-agents, autolearn, workflows. Auto-thinking classifier prompt/parse/effort map in `tools/zig/thinking_logic.zig` (host-tested); `thinking.zig` keeps provider resolution + fail-open `client.chat`; `thinking` guest same classify via `ck_llm`. `agent.reasoning_effort` (CLI `--reasoning-effort` on repl/run/goal) pins per-turn effort ahead of the classifier; the pin rides `ChatParams.reasoning_effort`, top of `writeSamplingParams` precedence (params > per-model config > sampling profile). The completion grant is the model's `max_tokens` (`turnCompletionBudget`), never `agent.max_tokens_per_turn` — that knob is the per-turn input/compaction floor, and sending it as `ChatParams.max_tokens` spent a reasoning model's 4096 grant on `reasoning_content` (run-1787011404). Autolearn recording stays native (every tool call/run); `autolearn` guest owns roadmap upsert and optional `--model` rewrite via `ck_llm`. Session ids are path fragments; every CLI/TUI/HTTP entry uses `session.zig` `validSessionId`. `listSessions`/`--continue` read only listing header (`message_count`/`bytes` before `messages`); pickers must not parse every transcript. `GET /api/sessions` relays `sessions` guest (`format=json`); mutations + full transcript stay native. `GET /api/providers` relays `providers` guest (`action:list`); live `/models` fill for empty map stays native (credentials), and usability annotation is native too (see `src/serve/`). Session search scores same header, then opens transcripts newest-first, stops at page limit. `sessions`, `graph`, `knowledge` guests use `ck_fs_read_range` — full `ck_fs_read` per file burns 1 MiB arena and drops later rows. Knowledge listing scalars (`doc_count`, `bytes`) before `docs`. Graph listing reads 4 KiB prefix (scalars before `task`/`nodes`), caps picker at 50 newest runs; 48 KiB × dozens of files used to exhaust arena mid-list. `state/runs/` mixes `run-<seconds>` and `sub-<nanoseconds>` (`subagent.zig`); newest = `graph_listing.lessThanChronological`, not filename sort — `sub-` > `run-` lexically, so filename sort filled newest page with oldest sub-runs. A run graph's `provider` is stamped in the persist defer from `self.provider` at exit, not only at start: `chatWithFallbackChain` repoints it to whoever served, and a start-only stamp recorded a provider that never answered (run-1787063448). `Agent.on_token` has no context arg, so streaming side-state (`stream_tally`, TTSR guard, `run_stream_socket`) is threadlocal; process-static would splice concurrent `/api/run` streams. `ttsr.buffer_bytes` clamped to `ttsr_buffer_bytes_max` (window allocated from run arena each LLM turn). History sent to model is append-only. DeepSeek rule: "model-visible means logged" — session is event log, next request *derived* from it, sent prefix never rewritten (mutating busts provider prompt cache). Compaction/prune/inject must project request-only copy (`requestMessages`/PRD 0031) or append replacement. Don't edit/delete saved message already sent. `session.compactMessages`/`maybeCompactMessages` still rewrite in-memory list; existing exceptions, not pattern. New model-visible input (system-prompt section, inject, tool result) must land in saved session, not just wire. Request-only prune persists omitted middle under `state/spills/<session>/` and leaves `[spill id=........]` locator on request copy; `spill` guest writes/reads file (loop decides which messages to spill, appends locator after guest confirms write). Deleting a session must take that conversation's text with it: `DELETE /api/sessions/<id>` also calls `spill` `forget` and `session_export` `forget`, because `state/spills/<session>/` and `state/exports/<id>.html` hold the same text under the session's own name and janitor deletes nothing on its own (ADR 0008). A new per-session store needs its own forget op on the guest that owns the path. The parallel `ToolWorker` builds its sandbox through `host.sandboxFor` (the single source of truth) and adds only the agent extras it knows about — a hand-rolled `Sandbox` literal there drifted four times (`exec_allow`/`env_allow`, `tool_self_name`, `session`) and each drift silently denied a parallel-run tool a capability the sequential path granted, the `session` one failing the `session_search` capability eval and stopping improve-self.
- `src/schedule/` — `clanker schedule`. Cron arithmetic is pure (no allocator/clock/`std.Io`) in `tools/zig/schedule_cron.zig` shared with `schedule` guest. Guest owns list/toggle/add/remove; `clanker schedule list|add|remove|enable|disable|log` and `/api/schedule` call it. `runner.zig` Fire callback stays native. Nothing fires alone; system cron calls `clanker schedule run-due`.
- `src/autoresearch/` — autoresearch driver (`harness.zig` + `loop.zig`). Outside protected surface so clanker can improve its research. Ledger write is `autoresearch` `op:"append"` (fs-scoped to `state/autoresearch/`); loop calls it sandboxed like `patch_apply`, sharing `tools/zig/autoresearch_logic.zig` (host-tested) for entry shape, stdout/stderr tails, best-metric compare. `src/autoresearch/harness.zig` stays native: harness contract is user-supplied shell command, `ck_exec` grants fixed allowlist + shell-operator deny tokens, so guest can't faithfully run it.
- `src/records/` — CLI half of the five record stores, one file per store (`reports.zig`, `research.zig`, `rfc.zig`, `adr.zig`, `prd.zig`) over shared `common.zig`. Each only renders: the store itself is the same sandboxed guest the agent calls, so CLI and agent share one implementation. `records/research.zig` is `clanker research` (notes); `src/autoresearch/` above is the unrelated experiment harness. Don't put a sixth store anywhere else.
- `src/stats/` — per-(provider,model) token usage (`tokens.zig`), appended at LLM client choke point to `state/token_stats.jsonl`. Failed completions also recorded (`ok:false`, `http_status`, `err`); successes-only log can't answer "is provider down?". `ck_stats` returns host aggregate, not raw log: shipping every record via 1 MiB guest arena fails after a few thousand lines. `improve_history`/`reasoning`/`autolearn` guests tail jsonl same way.
- `src/toolhost/` — native tool infra: `registry.zig` loads `*.tool.json`, `manifest.zig` validates, `builder.zig` compiles WASM, `usage.zig` accounts calls. `builder.zig` is anti-cheat boundary.
- `src/tui/` — libvaxis REPL (`clanker repl`). Mascot frames generated (`src/tui/mascot/gen_frames.py`); don't hand-edit `mascot_frames.zig` or pngs. Renderer order kitty → sixel → cells, from capability answer only; sixel lifecycle in libvaxis via `patches/vaxis-sixel-graphics.patch`, so `sixel_supported` in `mascot.zig` compiles path out on unpatched dep. `turn_stats.writeSession` matches web `#run-metrics` fields. Keyboard-owning modal in `repl.zig` (picker, search) must route Ctrl+C via `modalCtrlCAction` (ask modal has own stop path): fall-through `consumeAndRedraw` swallows interrupt and streaming turn can't be stopped while modal open. `/model`, `/theme`, `/effort`, `/preset` and the command palette are one shared picker (`PickerKind` + `drawModelPicker` + `handlePickerKey`) — extend it, never add a second modal; every `PickerKind` switch must gain the new arm (draw has five). Picker row/detail text must be static, arena, or a `Model` field buffer (`picker_pos_buf`/`picker_detail_buf`), never a draw-stack buffer: vaxis cells borrow slices until frame flush. `/model` candidates pass `providers.unconfiguredReason` (offline credential gate), so an unusable provider's models never list. A slash command sharing a CLI verb's name must do what the verb does: `/research` and `/rfc` reuse `research_cmd.run`/`rfc_cmd.run` (rendered text returned, printed by the CLI, folded into the transcript by the REPL — one implementation), and the old toggle that squatted on `/research` is `/websearch`. Multi-word args come from `splitCommandLine` (double quotes group; no escapes). Composer `vxfw.TextField` is single-line: raw `\n` would write into terminal cell, so breaks live as `newline_marker` (`⏎`) and only `takeComposerText` decodes — any path reading/filling field must use encode/decode helpers, not buffer directly. The marker glyph is never rendered (terminals disagree on U+23CE width; Konsole draws it wide, garbling the row): a buffer holding breaks draws via `drawComposer`, one row per line. Transcript `lines` entries are one logical row each — split multi-line text before appending, never store `\n` in an entry: `nextCell` refuses to absorb control bytes, but a raw `\n` cell still walks the terminal cursor off the row. Selection over the composer must highlight/extract through the composer child surface (parent cells under a composited child are blank and get covered). A reply fold's header row is its only toggle and `tailWindow` counts it in every state, so the draw loop must draw it (and register its `fold_hits` entry) in every state too — guarding it behind "not fully open" makes expansion a one-way door and desyncs layout by a row. `tailWindow` treats a fold as an atomic block only while collapsed/animating (drawn rows ≠ line rows there); a fully open fold counts per-line +1 header row at `f.start`, matching the draw's fall-through — block-counting it pinned scrolling at the header. A reply that folds also loses its `turn_arrow` (`foldForReply` strips it; the header is the turn marker). Scroll bounds are rows, never line counts: every guard/floor/dissolve takes `topWindowEnd` (wrap- and fold-aware row walk) via `scrollBounds`; comparing `line_count` to `avail_rows` re-breaks scrolling the moment anything wraps or folds. `last_text_width` is assigned only in draw — read it with the 80 fallback, don't add a second writer. Shift+Enter is enter+shift (kitty) or kp_enter (`ESC O M`, via `patches/vaxis-ss3-keypad-enter.patch`). Vendored deps log via `std.log`, routed by `std_options.logFn` in `src/main.zig` into `util/log.zig`; without it warnings bypass repl `.error_` threshold and paint over alt-screen. Inline `/` preview (`commandPreviewSpecs`) re-derives its rows from the composer text every frame and draws them into rows *reserved* above the frame the way the mascot's are; rows reuse the palette's session-lifetime `command_candidates` labels (vaxis cells borrow slices past the frame's return), and the band is suppressed while a modal picker is open.
- `src/mcp/` — MCP server. `src/acp/` — ACP v1 stdio. `src/hooks/` — Claude-compatible lifecycle hooks. `src/debug/` — DAP.
- `src/peers/` — mesh + chatrooms. Fleet lamp map `GET /api/mesh/map` (`mesh.buildMap`): self + `[[peers]]` + chat wires. Served even when `modules.mesh` off so HTTP peers still draw; `last_ts` is unix seconds, so pulse clock must be too. Page watches `GET /api/events` (SSE in `src/serve/live.zig`); membership + pending JOINs publish `t:mesh` like chat. `POST /api/*` stays command path. `chatrooms.fanOut` delivers each message to every peer's `/api/chat/message` via sandboxed `peers` (`chat_fanout`, `network_from_config` gating); the tool runner is injected from `cli.zig` at startup (`chatrooms.peers_runner`) because **no file under `src/peers/` may import `sandbox/`** — the sandbox host imports chatrooms for `ck_chat`, so any such import closes the peers↔sandbox cycle; host keeps per-peer backoff, passes guests in backoff as `skip`. `peers/phonebook.zig` is the same rule from the other side: it renders the guest's reply and nothing else, and `cli.zig`'s `cmdPhonebook` loads the guest through `toolJson` — the call `/api/peers` already shared. Local append seeks onto jsonl while under `max_history`; only trim rewrites. Conversational DMs are `chat_dm` (`ck_chat` with `to`); `peers` `notify` writes `state/notifications.jsonl` via `POST /api/notify`, not chat message. That store is the `notifications` WASM tool (record shape, 1 MiB ceiling, CAS dedupe-by-id append); the route relays the body to it and keeps only the status codes. Mesh `CHAT`/`CHAT_SYNC` received on wire, not fan-out path. Two `clanker serve` on one host mesh like two machines (loopback is address): need distinct `instance.id`, mesh port, web UI port, `agent.state_dir`. ## Everything is a plugin

Whatever can be a drop-in unit with a declared surface is one. Tools are guests + manifest; providers one vtable file + registry row; web UI views dirs under `ui/plugins/`; skills, prompts, themes, slash-command catalogs are data; REPL `/command`s and `clanker <command>` subcommands are manifests under `tui-plugins/` and `cli-plugins/` (PRD 0012) dispatching to sandboxed tools — add one there instead of editing `command_registry` or the `Command` enum (both are closed sets plus the plugin scan). Most units are sandboxed WASM, so plugin boundary doubles as security boundary. Before hardcoding capability, ask its plugin shape — sections below are that question for specific surfaces.

## WASM by default

Anything that can be a WASM tool must be. Harness is what cannot: sandbox, provider adapters, agent loop, improve engine, config, CLI arg handling. Everything else is a guest.

Not preference. Guests run under descriptor stating exactly which paths, commands, env vars, hosts they may touch; host enforces it. Native code in `src/` has whole process. Guests also replaceable without rebuilding clanker, letting improve loop change tool behavior without changing gate runner.

So, when adding a capability:

- `read_file hashes:true` + `edit_file op=hashline` is preferred edit pair: hashes are 4-hex xxHash32 per line (no newline), validated before write. Overlapping replacement ranges are refused (`OverlappingHunks`): hunks splice at offsets from the original line layout, so an overlap would consume the earlier edit or slice past the shrunk buffer. Exact `{old,new}` still works.
- Write it as guest with descriptor in `tools/manifests/`. Native code in `src/` needs reason surviving questions above. `clanker plugins new <name>` scaffolds both; `clanker plugins validate` checks and names offending key. Descriptor is whole sandbox policy; every honored field is in `docs/manifest.md` — loader ignores unknown keys, so typo'd grant is silent until tool fails. A workflow rule the model must *follow* (not just discover) goes in `prompt_guidance`: injected as `## Tool guidance` ahead of the catalog and echoed by `load_tools`. Write it precisely — "check against its own source" was read as re-reading the research note; name the mechanism (the cited URL/repo/file).
- Either language compiles to guest, host can't tell apart: `tools/zig/<name>.zig` built by `zig build tools` → `zig-out/tools/` (gitignored), or `tools/ts/<name>.ts` in AssemblyScript built by `npm run build:all` in `tools/ts/` → `tools/ts/dist/` (committed, not everyone has node toolchain). Descriptor `wasm` points to either. Zig is default (harness is Zig, `lib.zig` carries host bindings); use AssemblyScript when logic easier in TypeScript or already exists there. `clanker gate` never rebuilds `tools/ts/`, so `.ts` edit without `npm run build:all` ships stale `tools/ts/dist/*.wasm` silently; run `tools/ts/verify.sh` (rebuilds to scratch dir and diffs vs committed) before committing `tools/ts/` changes.
- CLI and web UI call the tool rather than reimplementing it, so tool stays single implementation. `toolText`/`toolJson` in `cli.zig` are that call.
- Web UI capability may want second descriptor over same wasm: one op per tool reads well in model catalog, one multiplexed entry suits HTTP endpoint. Mark that one `internal` to hide from catalog.

## Tool ABI

Guests export `scratch(need) -> u32`, `host_arena() -> u32`, `run(ptr, len) -> u64` (packed `(out_ptr << 32)|out_len`), and import `env.ck_*` in `tools/zig/lib.zig`.

## Self-improvement loop

Every promoted change must pass: `zig build`, `zig build test`, `zig build tools`, `zig fmt --check` (auto-formatted), source lint. Committed as `clanker: <summary> [imp-<id>]`. Run whole gate via `clanker gate`.

Those gates all ask same question — is change *safe*? A change doing nothing is maximally safe, so `src/improve/inert_check.zig` asks the other one. It classifies each proposal from staged source (never model-written summary) as `behavior`/`test_only`/`docs_only`/`inert`; engine refuses two shapes:

- **inert** — patch purely additive and every added function unreachable: nothing outside test block calls it. Helper + unit test for helper is not an improvement. Disable: `improve.inert_gate = false`.
- **test_only**, once `improve.max_consecutive_test_only` accepted improvements in a row were also test-only. Coverage is worth having; loop producing nothing else has stopped improving.

Class recorded in `state/improvements.jsonl` and rendered in history block of next prompt, so loop sees what it produced.

Each iteration plans before patching: one model call lists candidates (`src/improve/plan.zig` parses them), engine skips any whose words history already records as accepted/rejected, pins chosen idea's files into context, asks patch call to implement exactly that idea. Planning failure or dry run falls back to single-shot. Disable: `improve.plan_phase = false`.

`config.toml` may omit those keys. Struct defaults in `src/config.zig` (`capability_gate`, `inert_gate`, `plan_phase`) are then what next run loads, so flipping a default there equals writing `= false` in config. Loop rejects that, and `clanker eval --tasks` with no result lines is failed capability gate, not pass.

`src/gate/checks.zig` is writable so loop can strengthen its gates. Substring needle still matches if real work skipped by early `return .{ .ok = true }` above it as dead code; `checksZigShapeBroken` in `src/improve/engine.zig` refuses that shape (same as `cmdEvalShapeBroken` for `cmdEval`). `gate_invariants` also pins module bindings (`@import("../gate/checks.zig")` in `engine.zig`, `@import("gate/checks.zig")` in `cli.zig`): call-site needles match shadow module under different name, and `checks.zig` is only file `checksZigShapeBroken` inspects, so import line tells a rewire to `checks2.zig`-style stubs would otherwise leave.

## Living document

This file and `docs/prompts/*-review.md` are living docs. When a turn surfaces a caveat/quirk/failure worth remembering (build gotcha, sandbox edge, non-obvious gate firing), fold it into whichever file it belongs to before turn ends. One slice per turn: smallest true addition, not rewrite. When fewer words say the same thing, tighten instead of appending: trim to what still holds.

Before diagnosing failure, search [docs/reports/](docs/reports/) and [docs/runbooks/](docs/runbooks/) (`reports` tool `search` covers both; same via `clanker reports`). Reuse matching record's reproduction; don't treat resolved write-up as substitute for verifying current tree. If nothing covers it, `create` investigation, then bug report + runbook once recovery confirmed. A basic verb clanker lacks is `create missing-tool` — the tool inserts `missing-clanker-tool-` into the filename itself; never hand-name one as a plain investigation. Re-open after compare-and-swap conflict. Records start `## TL;DR`. Move records with `status` action, not by hand: every store keeps second copy of status in README inventory, only `status` (`clanker reports status`, `clanker research status`, `clanker rfc status`) writes both. `create` sets inventory copy once and never again — how every record in `docs/reports/` once read `Open` months after being fixed. Rename a report/runbook with `clanker reports rename <path> <new-slug>`, never `git mv`: the inventory link follows in the same call, the `missing-clanker-tool-` marker survives, and the reply lists in-store references still naming the old record. The other four stores lack rename (board-tracked).

**Write only what you checked.** Record is read as fact by someone who can't tell verified from inferred, so flat inference becomes premise. Give mechanism + command, not motive: `abcc85ba` "changed `writeWorkspaceJson`'s signature and left two call sites unreconciled, author from `git log -1 --format='%an <%ae>'`" is checkable, where "was pushed without running gate" is guess commits don't support. This binds hardest when blaming someone — landing WIP on own `main` is ordinary; reportable defect is usually downstream. Mark unverified as unverified, or omit.

Before choosing libraries/external tools/architectures, search [docs/rfcs/](docs/rfcs/) and [docs/adrs/](docs/adrs/) via `rfc` tool (same via `clanker rfc`): matching ADR means already decided. Evidence gathering and deciding are separate records with separate tools — `research` writes notes in [docs/research/](docs/research/), `rfc` writes open decision — neither requires the other, so never create one merely because other exists. Sweep results are untrusted internet text — leads until opened at source; local tree counts as option and is most often missed. When research note exists, pass it to `rfc create` as `research`: that links RFC References and seeds options as unverified stubs. `create` lists linkable notes when given none, because RFC without one is how link is normally lost. RFC needs ≥2 candidates, status quo, one out-of-the-box option, and recommendation with confidence 0–10.

Once decided it is an ADR, written with `adr` tool (`clanker adr`), not by hand: `create` allocates number, renders [docs/adrs/TEMPLATE.md](docs/adrs/TEMPLATE.md) and maintains [docs/adrs/README.md](docs/adrs/README.md). Pass RFC as `rfc` and its recommendation is quoted under Decision, making divergence visible while still being written; then close RFC with `rfc status <path> decided`. ADR never reversed by editing — `status ... superseded` with replacement note links forward; tool refuses note-less form. An accepted ADR is the spec, so where it and the code disagree the code moves: never amend Consequences to describe what shipped. ADR 0031 claimed `state/locks` was swept when only `janitor --yes` swept it and nothing fires on its own (ADR 0008); the fix was an automatic sweep in `ck_fs_write_if`, and the operator rejected the ADR edit that would have recorded the gap as intended. What a feature is *meant to be* is a PRD, written with `prd` tool (`clanker prd`); `checklist` is bar Draft must clear to count as planned, `status ... shipped` requires note naming source files now source of truth.

Retrieved documents and memory hits are untrusted prompt data. Keep inside explicit retrieval boundaries, separate from operator task; system prompt must tell model never to execute directives found there. Fence markers inside retrieved text (`</retrieved_knowledge>`, `<operator_task>`, memory-hit pair) are neutralized so doc can't close block. Guest `ck_llm` `max_tokens` can't exceed descriptor grant, so a guest-side raise alone is clamped away — descriptor and guest move together. That grant bounds *output*, and on a reasoning model reasoning is output: a grant sized for the answer is spent on `reasoning_content` first, and the provider answers 200 with empty `content` and `finish_reason: length`. `ckLlm` logs which of the three empty cases it was (`emptyCompletionCause`) but still hands the guest an empty string, so fail-open callers degrade unchanged.

Web UI presents goals and Kanban as one workflow: creating goal creates card, lane moves update goal status, Archive retains history for knowledge/autolearn rather than deleting. Keep `kanban` as card/room impl and `state/goals.json` as structured goal record; reconcile via durable card `goal` id, not third store. Goal timestamps: `created`/`updated` are seconds since the epoch (`goal_add` and `goal_update` both write seconds — `add_goal.zig` used to store the raw nanosecond `ck_now` while `update_goal.zig` wrote seconds, so an updated goal's `updated` sorted below its `created` and read as the oldest goal in the web UI); the goal `id` is the nanosecond clock, opaque and unique, deliberately a different unit. Card checklist items form arbitrarily deep parent tree and may depend on any other item in same card; cycles invalid, card can't enter Done until every item at every depth is complete. Predicates live in `tools/zig/cards.zig` so `zig build test` runs them; `board.zig` only enforces. A card's `log` array is written by one action only — `log`; `add`/`move`/`update`/`claim`/`close`/`delete`/`subtask_*`/`depend` append nothing, so the card logs are not the board's history and reading them alone shows an active board as idle. Every action is in the room log, but only as far back as `max_history`; `boardTimeline` (`ui/app/lib/board.js`, `api.boardTimeline`) merges both feeds and is what a history view should use.

Goal surfaces have three separate effects: `write-goal` drafts without saving/running; `add-goal` saves without starting work; `goal`/`/goal` starts a goal loop until condition achieved, blocked, cancelled, or budget-limited. Catalog tools are `goal_write`, `goal_add`, `goal_update` (noun_verb, like `todo_*`). `run --goal <id>` starts same loop from saved record. Never describe or implement `goal` as one normal agent run. `goal_write`'s five draft fields must stay distinct: `tools/zig/write_goal_logic.zig` (host-tested, imported by the guest) extracts per-sentence/clause segments of the intent, defaults an open fork under Assumed / Still open, and defaults a fork whose only matching text another field already holds — the raw intent appears once, as `record.intent`, never as a field value.
